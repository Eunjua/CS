# 케어아카데미 문의 — AI/사람 처리 구분 기준 (통합본)

작성: 2026-06-18 | 대상: 케어아카데미 | 근거: AI 상담 채팅 172건 (2026-05-23~06-17) 전수 분석·정독

---

## 1. 한 장 요약

- **목적:** "AI가 풀 문의 vs 사람이 풀 문의"를 가르는 판단 기준을 데이터로 만들고, 봇 개선 우선순위를 도출.
- **핵심 발견:** 사람이 이관받아 처리한 건의 **대부분이 "표준 안내문 복붙"**이었다. → AI 자동화 여지가 생각보다 훨씬 크다.
- **결론:** 전체 문의의 **약 83%(143건)는 AI가 지금 또는 약간의 개선으로 처리 가능**, **약 17%(29건)만 진짜 사람이 필요**.
- **즉시 실행:** **38%(66건)는 개발 없이 "표준 답변만 봇에 심으면" 바로 자동화**된다.

## 2. 판단 기준 (재사용 가능한 규칙)

이 기준은 앞으로 새 문의를 분류할 때도 그대로 적용합니다.

### 2-1. 5단계 분류 (각 분류가 무슨 뜻인가)

문의를 아래 6개 코드 중 하나로 라벨링합니다. **①·②·③ 큰 갈래**를 먼저 잡고, ②와 ③은 세부로 나뉩니다.

| 코드 | 이름 | 정의 — 이 분류는 무슨 뜻인가 | 대표 예시 | 처리 방향 |
|---|---|---|---|---|
| **①** | 현재 AI 완결 | 봇이 사람 개입 **없이 이미 끝낸** 문의 | 자격증 발급과정 안내, 단순 정보 질문 | 유지 |
| **②-A** | 즉시 자동화 | 답이 **표준 안내문·파일로 정해져 있고 시스템 조회가 필요 없는** 문의. 지금은 사람이 매번 복붙 중 | 수강취소(자동종료 안내), 교육자료 파일, 수강방법, 자격증 비용 | **표준답변을 봇에 탑재 (개발 거의 無)** |
| **②-B** | 시스템연동 자동화 | 답은 정해졌으나 배송·결제·정보를 **백엔드에서 조회/수정해야** 하는 문의 | 배송조회, 입금확인, 결제기한 연장 | 백엔드 연동 후 자동화 |
| **③실작업** | 사람 — 실작업 | 실제 **금전 작업**(환불·결제처리)이나 **개인정보 변경**(본인확인 필요)이라, 봇이 틀리면 금전·개인정보 리스크가 큰 문의 | 결제수단 변경, 환불, 주소·이름 변경 | 사람 처리 |
| **③감정** | 사람 — 감정·전화 | 컴플레인·불만·전화 연결 고집 등 사람의 **공감·판단이 본질적으로 필요**한 문의 | 화난 고객 응대, 전화 요구 | 사람 처리 |
| **③기술** | 사람 — 기술오류 | 앱·동영상 장애나 AI 오답 등 **제품/개발 수정**이 필요한 문의 | 강의 재생 오류, 버튼 오표시 | 개발 수정 |

> 엑셀 `이관사유_상세` 시트의 **5단계 분류** 컬럼이 이 코드를 그대로 씁니다. **없앨수있는이관 = Y**(②-A·②-B, 봇 개선하면 사라질 이관) / **N**(③, 사람 유지) / **-**(①, 이미 봇 완결).

### 2-2. ②↔③ 경계 규칙 (2-gate)

어떤 유형이 "지금 AI가 못 함"일 때:
- **③ 사람**으로: ⓐ 사람의 **판단·공감이 본질적으로 필요**하거나, ⓑ 틀렸을 때 **리스크(금전·개인정보·신뢰)가 큰** 경우
- **② 자동화 대상**으로: 위 둘 다 아니면 (= 답을 규칙화/안내문화 가능 + 오답 리스크 낮음)

### 2-3. ②-A ↔ ②-B 구분

- **②-A:** 봇이 **말(표준 답변·파일 첨부)만** 하면 끝 → 개발 거의 불필요
- **②-B:** 봇이 **백엔드를 조회/수정**해야 함 (배송상태, 결제여부, 주소변경) → 시스템 연동 필요

### 2-4. 사람 영역 신호 (③ 트리거)

감정·컴플레인 / 통화·전화 고집 / 복잡·예외 / 금전 직접 작업(결제·환불) / 개인정보 변경(본인확인) / AI 오답·기술 장애

## 3. 데이터 & 방법

- **데이터:** 케어아카데미 채팅 172건(태그 + 대화 전문 1,624개 메시지).
- **판정 신호(1순위):** ① 상담원 이관 태그, ② 대화 내용 직접 정독. (만족도는 보조 — 아래 한계 참고)
- **검증 과정:** 태그로 1차 분류 → **172건 전체를 id별로 한 건씩 정독**하여 5단계 분류·이관사유를 확정(엑셀 `이관사유_상세` 시트).
- **핵심 교차검증:** 태그 상태는 완료 40 / 이관 76 / 미상(태그누락) 56. "AI완료" 40건은 대화에 사람 메시지 0개 → 태그 신뢰 확인. **'미상' 56건도 대화를 읽어 직접 분류**(대부분 ① 봇 완결 또는 ②-A 표준안내였음).

## 4. 통합 분류 결과 (172건)

| 버킷 | 건수 | 비율 | 액션 |
|---|---|---|---|
| ① 현재 AI 완결 | 54 | 31% | 유지 |
| **②-A 즉시 자동화 (안내문·파일)** | **66** | **38%** | **표준답변 봇 탑재 (개발無)** |
| ②-B 시스템연동 자동화 | 23 | 13% | 백엔드 연동 |
| ③ 실작업 (금전·정보변경) | 17 | 10% | 사람 처리 |
| ③ 감정·전화 | 7 | 4% | 사람(감정 케어) |
| ③ 기술오류 (개발) | 5 | 3% | 개발 수정 |

**→ AI 처리 가능(①+②) = 143건 (83%) / 진짜 사람(③) = 29건 (17%)**
**→ 이관·종결된 118건(②+③) 중 89건(75%)이 "없앨 수 있는 이관"(봇 개선 시 사라짐).**

- **결제**는 ① 0건 — 전부 ②-B(조회 13) 또는 ③(금전작업 5). 금전 영역은 시스템 연동/사람.
- **일자리**는 13/19가 이미 AI 완결.
- **자격증**은 갈래가 가장 다양 — 비용·발급(②-A) / 배송(②-B) / 주소·이름변경(③실작업) / 앱오류(③기술)가 섞여 있음.

## 6. 한계 & 다음 단계

1. **만족도 미반영** — 만족도설문.xlsx의 id가 채팅 172건과 0건 매칭(서로 다른 채팅 묶음). 같은 기간 export 재확보 시, *"AI완료인데 사실 불만족(숨은 실패)"* 검증 가능.
2. **AI완료 54건의 답 품질 미검증** — 봇 메시지가 export에 없음. 만족도 매핑되면 확인.
3. **표본 1개월·172건** — 빈도 낮은 유형은 신뢰도 낮음. 기간 확대 시 안정.
4. **②-A 66건은 분류만 끝남** — 표준 답변을 실제로 봇에 탑재하는 작업은 별도.
6. **이관사유는 추론값** — 채널톡에 "이관 사유" 항목이 따로 없어, 대화를 읽고 사유를 붙인 것(객관 기록이 아닌 정독 기반 판단). 의심 건은 `이관사유_상세` 시트의 url로 원본 확인 가능.
5. **②-B 정보수정은 본인확인 리스크** — 자동화 시 본인확인 절차 설계 필요(아니면 ③ 유지).
