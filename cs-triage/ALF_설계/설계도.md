## 왜 다시 짜나 (같은 문제를 반복하지 않기 위해)

1. **같은 사실이 여러 곳에 있다** — 자격증 결제·배송이 `자격증_신청방법`과 `수강정책` 7번에 둘 다. FAQ와 docs가 나이 제한을 다르게 말한 적도 있다.
2. **기준 지도가 없다** — 개선이 "이번 주 틀린 상담" 단위로 쌓여 문서에 괄호 패치가 늘었고, 어떤 상황이 아직 비어 있는지 모른다.
3. **어디에 넣을지 기준이 없다** — 순서 문제를 문서로, 태도 문제를 태스크로 고치는 일이 생겼다.

## 구조 — 5층

```
0층  경계선      봇이 하는 일 / 사람이 하는 일
1층  상황 지도   고객 여정 × 상태 = 모든 상황의 목록  ← 설계의 중심
        ↓ 상황마다 "처리 방식"을 정하면 들어갈 곳이 정해진다
2층  지식        FAQ · 아티클 · 엑셀   (안내만 하면 끝나는 상황)
3층  흐름        태스크               (조회·분기·상담원 연결이 필요한 상황)
4층  태도        규칙                 (모든 상황 공통 말투)
5층  점검 루프   매주 /알프가 상황 지도 줄 단위로 채점
```

### 0층. 경계선
`케어아카데미_AI사람_구분기준_통합본.md`의 레드라인을 그대로 쓴다.
**"조회·안내는 봇, 바꾸기·되돌리기·돈·감정은 사람."**
새 상황이 생기면 이 기준으로 먼저 처리 방식을 정한다.

### 1층. 상황 지도 (`상황지도.md`)
한 줄 = 한 상황. 칸:

| 칸 | 뜻 |
|---|---|
| 여정 단계 | 아래 목록 중 하나 |
| 고객 상태 | 같은 질문이라도 상태가 다르면 답이 다르다 → 다른 줄 (예: 신청함·미입금 / 결제 완료·발송 전 / 발송됨) |
| 상황 | 고객이 원하는 것 |
| 고객 표현 | 실제 상담에서 쓴 말 2~3개 — FAQ 동의어·아티클 제목의 재료 |
| 처리 방식 | **안내**(답이 정해짐) / **조회**(시스템 상태를 봐야 답이 나옴) / **사람**(경계선에 걸림) |
| 들어갈 곳 | 처리 방식으로 자동 결정 — 안내 → FAQ·아티클·엑셀 중 하나 / 조회·사람 → 태스크 |
| 연결 조건 | 봇이 어디까지 하고 언제 사람에게 넘기나 |
| 근거 | 개선로그 차수·chatId |

여정 단계:
가입·로그인(본인인증 포함) → 수강 신청·수강 → 시험 → 자격증 신청 → 결제 → 배송 → 수령 후(재발급·정보수정)
여정 밖: 취소·환불 / 과목·자격증 정보 / 일자리 / 기타(이벤트·앱 오류·사람 요청·운영시간)

### 2층. 지식 — 유형별 쓰는 법

채널톡 안내 기준:

| 유형 | 맞는 내용 | 찾는 방식 | 쓰는 법 |
|---|---|---|---|
| **FAQ** | 짧은 단답형 질문 ("비밀번호 잊어버렸어요") | 고객 질문 **전체**가 얼마나 비슷한지 | 질문 하나 = 답 2~3문장. 동의어 칸에 상황 지도의 "고객 표현"을 넣는다. 긴 질문엔 약하다 |
| **아티클** | 장문 정책, 자주 고치는 내용, 조건이 여러 개인 안내 | **제목**의 단어가 고객 질문에 들어 있으면 매칭 | 제목에 고객이 실제로 쓰는 핵심 단어를 넣는다. **아티클 안에 표 금지** (잘 못 읽어 오답이 난다) → 표는 문장으로 풀거나 엑셀로 |
| **엑셀** | 항목값이 정해진 표 (상품·가격·특이사항) | 행·열 | 과목 상세 50여 개 → 한 행 = 한 과목 |

원칙:
- **한 사실은 한 곳에만.** FAQ와 아티클이 같은 걸 말해야 하면 문장을 똑같이 쓰고, 상황 지도의 "들어갈 곳"에 둘 다 적어 둔다 (바뀔 때 같이 고치기 위해).
- 금액·기한처럼 바뀌는 숫자는 `상황지도.md` 아래 **숫자 위치표**에 어디 있는지 적는다.
- 안내 문구는 상태를 첫 문장에 단정한다 ("아직 결제 전이에요"). 주 고객 60~70대.

### 3층. 흐름 — 태스크
상황 지도에서 처리 방식이 **조회·사람**인 줄만 모은 것 = 태스크가 다뤄야 할 목록.
지금 노드를 이 목록에 대응시켜 필요 없는 노드·빠진 분기를 찾는다. 노드 단위로 고친다.

### 4층. 태도 — 규칙
모든 상황에 공통인 것만 남긴다 (말투·금지 표현·연결 시 대기 안내·고객 정보 확인).
특정 상황 이야기가 들어 있으면 지식이나 태스크로 옮긴다. 규칙 2000자 제한.

### 5층. 점검 루프
`/알프`가 상담마다 **상황 지도의 어느 줄인지** 붙여 채점한다 → 줄 단위 봇 완결률.
지도에 없는 상황이 오면 새 줄 후보.

## 실제 상담 원문의 역할 (10/28 추가)

개선로그는 **봇이 틀린 상담만** 모은 기록이라, 잘 된 상황과 빈도가 빠져 있다. 원문(`채널톡/처리완료/`, 10/5~10/25 3주)을 두 군데에 쓴다.

1. **지도 검증** — 3주 상담의 첫 질문을 전부 지도 줄에 붙인다. 어느 줄에도 안 맞는 상담 = 지도에 빠진 상황. 줄마다 "3주 건수 · 봇 완결 %"가 붙어 우선순위가 숫자로 나온다. 이 3주가 **교체 전 기준선**.
2. **시험지(테스트셋)** — 줄마다 실제 고객 첫 질문 3~5개(개인정보 가림). 교체 전엔 채널톡 AI CoS 미리보기에 넣어 확인, 교체 후엔 `/알프`로 그 줄의 봇 완결률을 기준선과 비교.

- 봇 완결 판정 = 상담원 공개 발화(isPrivate=False) 없음 (18차부터 쓰는 기준).
- 시험지는 개인정보를 가려도 고객 말투가 그대로라 **git에 올리지 않는다** (보관 위치는 시험지 만들 때 정함).
