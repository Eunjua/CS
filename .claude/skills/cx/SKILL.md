## 2. `/cx` — 매일 오전 10시 · 오늘 정하기

**3분 안에 끝나야 한다.** 아침 루틴이 무거우면 안 하게 된다.

### 보여줄 것 (3~5건)

1. **진행중**인 것
2. **착수일이 오늘 이전**인 것 (오늘 것 + 밀린 것)

착수일이 안 찍힌 과제는 **보여주지 않는다.** 그건 이번 주에 하기로 안 한 것이다.

### 형식

- 과제명 한 줄 + **연결(KR2 / KR3 등)** 을 함께 표시. 이 일이 무엇을 위한 건지가 보여야 우선순위가 안 흔들린다.
- 설명·메모는 펼치지 않는다.
- 착수일이 지났으면 `(N일 밀림)` 표시
- 마지막 줄: **"오늘 뭐 하실래요?"**

> **KR 진척 수치(예: AI 해결율 37%)는 띄우지 않는다.** 보드에 없고 금방 낡는다.
> KR 자체는 「2. 목표」에 있고, 보드는 **실행 과제만** 담는다. 최신 수치는 「ALF 개선 추적」에 회차별로 누적돼 있으니 `/cx alf`에서 본다.

### 고른 뒤

- 고른 것 → `착수일 = 오늘`, 필요하면 `상태 = 진행중`
- 안 고른 밀린 것 → 그대로 둔다. 내일 다시 뜬다.

### 3일 이상 밀린 과제

착수일이 **3일 이상 지난** 과제가 있으면 반드시 묻는다:

> *"이거 3일째 밀리고 있는데, 정말 할 건가요? 아니면 쪼개거나 보류할까요?"*

계속 밀리는 건 대개 **안 할 일**이거나 **너무 커서 쪼개야 하는 일**이다. 이걸 잡아내는 게 이 루틴의 핵심 값어치다. 그냥 넘기지 말 것.

## 3. `/cx 주간` — 월요일 · 이번 주 정하기

15분. 위클리 회의 후에 하는 것을 기본으로 한다(회의에서 나온 일까지 반영하려면).

### 순서

**① 지난주 리뷰**
지난주 착수일이 찍혔던 것들을 훑는다. 된 것 / 안 된 것. 안 된 것은 왜인지 한 줄씩.

**② 안 된 것 처리**
이번 주로 다시 가져올지, 보류할지 **하나씩 묻는다.** 자동으로 이월하지 않는다.

**③ 이번 주 고르기**
우선순위 높은 것부터 제안하되, **예산을 넘기지 않는다.**

> 주 가용 시간 ≈ **14시간** (화~금 4일 × 3.5시간). 월요일은 위클리 회의와 제작 리스트로 차 있다.
> 고정 지출: ALF 분석 사이클(주 1회), 매일 제작 리스트 전달 약 10분.

**④ 요일별 배분**
고른 것에 `착수일`을 **화~금**으로 뿌린다. 월요일에는 찍지 않는다.
큰 과제는 여러 날에 나눠 찍어도 된다(같은 과제를 화·수 이틀에 걸쳐).

**⑤ 마무리**
이번 주에 하기로 한 것을 표로 한 번 보여주고 끝낸다.

## 5. 보드 반영 규칙

### 묻지 않고 바로 반영

- *"이거 끝냈어" / "했어"* → `상태=완료`, 메모 앞에 `[완료 YYYY-MM-DD]` + 결과 한 줄
- *"하는 중"* → `상태=진행중`
- *"나중에"* → `상태=보류`, 메모에 **왜 보류인지** 반드시 남긴다
- 착수일 이동, 우선순위 **하향**

### 반드시 물어보고 반영

- **새 과제 추가** — 대화 중 스쳐간 아이디어를 다 넣지 않는다. *"이거 과제로 넣을까요?"*
- 과제 삭제·통합
- 우선순위 **상향**
- **분기 이동** (26-3Q → 26-4Q 등) — 이번 분기에서 빼는 결정이므로 반드시 확인

> 보드가 길어지면 안 보게 된다. 2026-08-04에 20건을 15건으로 걸러냈고, 그중 살아남은 건 5건뿐이었다.

### 보드에 담는 것 / 안 담는 것

| | |
|---|---|
| **담는다** | **따로 시간을 잡아야 하는 일** (몇 시간~며칠) |
| **안 담는다** | **다른 곳이 이미 추적하는 것** — ALF 규칙 개정·docs 보강은 「ALF 개선 추적」이, KR 진척은 「2. 목표」가 관리한다 |

> 두 곳에서 같은 걸 관리하면 연동이 필요해진다. **연동을 만들 게 아니라 한 곳에서 빼는 게 맞다.**
> ALF 개선점을 보드에 올릴지는 **`/alf` 스킬 마지막 단계(10번)에서 판단**한다. 여기서 따로 챙기지 않는다.

### 방향에 관한 결정이 나오면

「1. CX 팀이란」 4부 **결정 이력** 표에 추가한다. `날짜 / 결정 / 재검토 조건` 세 칸. 없으면 `—`.
정체성·범위·원칙에 관한 것만. 실행 방법은 보드 메모로 충분하다.

## 6. 지켜야 할 것

- **목록을 길게 늘어놓지 않는다.** 일간 3~5건, 주간도 표 하나.
- **새 일을 제안하기 전에 있는 일을 끝내는 걸 돕는다.** 분기 예산이 약 90시간뿐이다.
- **추정치는 추정이라고 밝힌다.** 소요 시간을 아는 척하지 않는다. 실측치가 있으면 그것을 쓴다.
- **상담원에게 새 업무를 넘기는 제안은 하지 않는다.** 상담원은 CS 대응만 한다(2026-08-04 결정). 외부 업체 소통도 리드 업무다. 다만 *상담을 끝까지 마치는 것*(환불 처리·정보 수정)은 상담원 업무에 포함된다.
- **데이터 없이 단정하지 않는다.** 후처리 요청 로그·ALF export 같은 실제 데이터가 있으면 그것을 근거로 말한다.
- **메모의 근거를 지어내지 않는다.** 과제를 추가할 때는 **사용자가 말한 것만** 적는다. 배경·목적·효과를 추론해서 채우지 말 것. 아는 맥락에 끼워맞추면 그럴듯한 오답이 되고, 몇 주 뒤에 그 메모를 근거로 잘못 판단하게 된다. **모르면 비워두고 한 줄로 물어본다.**
- **보드가 손으로 수정돼 있을 수 있다.** 조회 결과가 기억과 다르면 조회 결과를 믿는다. 아카이브된 과제는 건너뛴다.
