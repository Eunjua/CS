# 은주에게 온 요청 기록 스킬

목적: **상담원이 하루에 은주에게 요청을 얼마나 하는지** 매일 센다. 날짜별·상담원별·유형별 건수가 쌓이는 게 핵심이고, 처리 여부는 기록하지 않는다(은주 결정, 2026-10-07).

- 시트: [은주에게 요청한 것들 · 시트3](https://docs.google.com/spreadsheets/d/1TEiCEEOwz-V6sgJ3B61Yn49WYGFRoEjqHnR6d0Uygk8/edit?gid=1298766334#gid=1298766334) — A 날짜 · B 요청자 · C 유형 · D 내용 · E 링크
- 웹앱: `gas-request-log/` (시트에 붙은 앱스크립트, clasp). 이 스킬의 `send_rows.py`가 부른다
- 슬랙: `#보살핌_고객센터` = `C098HRB3HBK` · `#all_요청하기` = `C031ESUAY0P` · 은주 = `U06PJ85ML7R`

## 1. 날짜 정하기
- 날짜를 말하면 그날. 없으면 **오늘(한국시간)** 으로 하고 어느 날인지 첫 줄에 밝힌다.
- 여러 날이면 하루씩 반복한다.

## 2. 유형 목록 받기
```
python3 .claude/skills/request-log/send_rows.py types
```
시트 H1 드롭다운 목록이 나온다. **C열 유형은 이 목록에 있는 이름을 글자 그대로만** 쓴다. 웹앱이 목록에 없는 유형은 통째로 거절한다.

## 3. 슬랙 읽기
```
python3 .claude/skills/request-log/send_rows.py range 2026-10-07   # → oldest / latest
```
두 채널을 같은 oldest/latest로 읽는다. `slack_read_channel(channel_id=…, oldest=…, latest=…, limit=100)` — "more messages"가 나오면 cursor로 끝까지 읽는다.
- `C098HRB3HBK` (#보살핌_고객센터) — 4단계 A 기준
- `C031ESUAY0P` (#all_요청하기) — 4단계 B 기준. 하루 0건인 날이 흔하다(10/5·10/6 모두 0건)
**스레드는 열지 않는다.** 스레드 안 태그는 진행 보고라 세지 않는다(10/5 확인: 스레드 안 태그 3건 모두 "전달 완" 류).

## 4. 넣을 것 / 뺄 것
### A. #보살핌_고객센터
넣는다 — 본문(채널 최상위) 메시지 중 `<@U06PJ85ML7R` 이 들어간 것:
- 상담원이 직접 쓴 요청
- 환불요청 양식(봇 `B0ARJAPR3L7`) — 요청자는 양식 안 `요청자:` 이름
- 전날 요청을 다시 묻는 **후속 문의**도 넣는다(10/6 은주 확인)

뺀다:
- 은주 본인이 쓴 글
- 은주 없이 다른 사람만 태그한 글 (예: 이지영 → 전지수)
- 봇 공유 글 (`부재중 건수 공유` 등)
- **요청이 아닌 공유·보고** — "추가 환불 요청 없음", "키인 결제 참고"처럼 은주가 할 일이 없는 글 (10/7 은주가 제외 지시)
- 채널 참여 알림

### B. #all_요청하기 — 「CS 대응 요청」 워크플로우만
워크플로우 글은 이렇게 생겼다 (보낸 사람이 `CS 대응 요청` 또는 빈 이름 `:`으로 보일 수 있음 — **본문 모양으로 판단**):
```
요청자: <@U…|전지수>
<!subteam^S04HB6E4Y1W>
*요청유형*: 시스템 처리 요청 | 정보 변경/삭제 | 서비스 오류
*서비스*: 아카데미 | 케어파트너 기관 | 기타
*고객정보*: …
*[문제 상황]* … *[요청 사항]* …
```
- `요청자:` + `*요청유형*` 이 둘 다 있는 본문 글만 넣는다. 그 채널의 다른 글(계정·권한 요청, 사내 공지 등)은 은주 태그가 있어도 넣지 않는다
- **요청자가 은주 본인이어도 넣는다** — requester는 `은주(CS대응요청)` (10/7 은주 요청: CS가 낸 요청 전체를 센다). #보살핌_고객센터의 은주 본인 글은 여전히 뺀다
- 스레드는 열지 않는다

애매하면 넣지 말고 4단계 표 아래에 "뺀 것" 목록으로 따로 보여준다.

## 5. 줄 만들기
| 칸 | 규칙 |
|---|---|
| date | `YYYY-MM-DD` (한국시간 기준 메시지 날짜) |
| requester | 상담원 이름만(`전지수`·`허민강`·`이지영`). 환불 양식이면 `전지수(환불양식)`, CS 대응 요청 워크플로우면 `전지수(CS대응요청)` (은주 본인이면 `은주(CS대응요청)`) |
| type | 2단계 목록 중 하나, 글자 그대로. 맞는 게 없으면 은주에게 묻는다 — 지어내지 않는다 |
| type 참고 | 10/5·10/6에 쓴 연결 — 주소지 변경 → `자격증 정보 수정` · 파손 재발송·주소 오류 반송 → `오배송 / 오제작 / 파손` · 도착 예상·합배송 → `배송/송장번호확인` · 상담 이관·제휴 문의 → `CS대응 관련` · ALF 오류 → `서비스 오류` · 소보원·언론 제보 언급(환불 요청이 본론이면 `환불`) → `신고` |
| CS 대응 요청 유형 | 워크플로우의 `요청유형`이 아니라 **문제 상황 내용**으로 드롭다운에서 고른다 — 생년월일·주소·이름 변경 → `자격증 정보 수정`, 안심번호·알림·결제 반영 등 시스템이 잘못 동작 → `서비스 오류`, BO에서 처리 안 됨 → `BO 오류`. 내용 앞에 서비스를 붙인다 (예: `[아카데미] 고령자 생년월일 입력 요청`) |
| 후속 문의 | 유형은 원래 요청의 주제로 고르고, 내용 앞에 `[후속]`을 붙인다 (예: `[후속] 10/5 스캔본 요청 일정 확인`) |
| content | 한 줄 요약. **고객 이름·전화번호·계좌번호·주문번호(OD)는 쓰지 않는다** (자격증명·사유·마감은 OK) |
| link | `https://bosalpim.slack.com/archives/C098HRB3HBK/p` + ts에서 점 뺀 숫자 (예: ts `1791190000.285489` → `p1791190000285489`) |

## 6. 먼저 보여주고 넣기
1. 표(시간·요청자·유형·내용)와 **요청자별 건수**, "뺀 것" 목록을 보여준다.
2. 은주가 OK하면(또는 처음부터 "바로 넣어"라고 했으면) 줄을 JSON 파일로 저장해 보낸다. 파일은 작업용 임시 폴더에 둔다(저장소에 두지 말 것).
   ```
   python3 .claude/skills/request-log/send_rows.py append <rows.json>
   ```
3. 응답의 `added`(새로 들어간 줄)·`skipped`(이미 있던 링크라 건너뜀)를 보고, `rows`(시트에서 다시 읽은 값)가 보낸 것과 같은지 확인해 보고한다. 같은 날을 다시 보내도 `skipped`로 빠지니 중복 걱정은 없다.

## 실패하면
- `JSON이 아닌 응답` / 403 → 권한이 풀린 것. `gas-request-log/`에서 `clasp open-script` → 편집기에서 `authorize` 실행 → 허용 후 재시도
- `유형이 드롭다운에 없음` → 응답의 `types` 목록과 대조해 고쳐서 다시 보낸다
- `시트 첫 줄이 … 가 아님` → 누가 A~E 머리글을 바꾼 것. 은주에게 확인
- 그래도 안 되면 탭 구분 줄을 `pbcopy`로 복사해 두고 은주에게 시트3 빈 줄 A칸 ⌘V를 부탁한다
