## `상태` 5종 — 이 정의대로만 쓴다

| 상태 | 언제 쓰나 |
|---|---|
| `완료/해소` | **2회 연속** 재발 없음이 확인됨. 한 회차 0건으로는 못 준다 |
| `미해소` | 확인했는데 그대로거나 악화됨. 회차를 넘어 살아있는 것 |
| `계속 추적` | 조치는 했고 효과 판정이 아직인 것 + 사례가 없어 판정 못 한 것 |
| `부분 확인` | 여러 갈래 중 일부만 확인됨(나머지 갈래를 결과 칸에 명시할 것) |
| `미확인` | 제안만 하고 손 안 댐 · **추적이 끊긴 것** |

## 8-A. 📊 개선점 DB 갱신 (필수·먼저)

상태의 단일 출처다. 여기가 안 맞으면 다음 회차에 또 항목이 새어나간다.

- **`회차` select에 이번 회차 옵션이 없으면 먼저 추가**한다. `notion-update-data-source`로 `ALTER COLUMN "회차" SET SELECT(...)` — **기존 옵션(`3분기 이월`·`18차`…)을 전부 다시 적고** 새 회차를 더한다(빠뜨리면 옵션이 지워진다). 빈칸으로 두지 말 것.
- **진행순서 5-1 확인 목록의 모든 행**에 대해 `상태`와 `다음 분석 결과`를 갱신한다 (`notion-update-page` + `update_properties`).
  - `다음 분석 결과`는 **기존 텍스트를 지우지 말고 아래에 이어 붙인다** — `기존내용\n[{N}차 {MM-DD}] {판정} — {근거·수치, 채널별 건수}`. 회차별 경과가 한 칸에 쌓여야 "몇 회째 이월인지"가 보인다.
  - 기존 텍스트가 필요하므로, 수정 전 그 행의 `다음 분석 결과`를 먼저 조회한다.
- **이번 회차 신규 개선점은 행을 추가**한다 (`notion-create-pages`, parent는 `data_source_id`). `회차`·`처음 발견`(`{N}차`)·`점검일`·`분류`·`상태`·`배경 (왜)`·`확인 방법`·`관련 지표/영향`을 채운다.
  - `확인 방법`은 **"다음에 무엇을 몇 건에서 몇 건으로 세면 됐는지 알 수 있나"**로 숫자 기준선을 박아 쓴다. 채널별 기준선이 다르면 둘 다 적는다.
  - 조치를 막 한 것은 `계속 추적`, 제안만 하고 안 고친 것은 `미확인`.
- **행을 지우지 않는다.** 해소된 것도 `완료/해소`로 남긴다 — 뒤집힌 전례가 있어 이력이 근거가 된다([past-cases.md](past-cases.md)).

## 8-B. 📈 추이 DB에 이번 회차 행 두 개를 추가한다 (필수)

`collection://113a0408-eb0f-44ac-90d9-a8a4cc17dd99` (`notion-create-pages`, parent는 `data_source_id`)

🔴 **매 회차 채널별 두 행을 빠뜨리지 말 것** — `{N}차 (케어아카데미)` · `{N}차 (케어파트너)`. 한 채널 export가 없으면 그 행은 만들고 `이 회차에 무슨 일이`에 "export 없음"이라 적는다(차트가 비는 이유가 남게).

채울 칸 (비율은 **소수로** — 56.4%는 `0.564`):

| 칸 | 값 | 출처 |
|---|---|---|
| `회차`(title) | `18차 (케어아카데미)` | |
| `채널` | `케어아카데미` / `케어파트너` — 빈칸이면 차트에서 빠진다 | |
| `점검일` | 점검한 날 | |
| `관여율` | 채팅 상담 중 알프가 발동한 비율 | **은주 값** (진행순서 1번에서 받는다) |
| `해결률` | 알프가 관여한 상담 중 상담원 없이 끝난 비율 | **은주 값** |
| `이탈률` | 이탈 ÷ 분모 | measure.py (참고) |
| `봇완결률` | 봇완결(상담원 공개 발화 없음) ÷ 분모 | measure.py (참고) |
| `KR2 감당 건수` | 그 채널 상담원 1인 하루 감당 건수 | 아래 식 |
| `이 회차에 무슨 일이` | 3~5줄 요약(최대 발견·닫은 것·되살아난 것·분모 주의) | |

- **KR2 감당 건수** = 480 ÷ [ (1 − 관여율) × 4.0 + 관여율 × (확인 2.5 + (1 − 해결률) × 4.0) ]. 확인 시간 2.5분·상담 시간 4.0분은 은주가 바꾸면 그 값을 쓴다(계산기 https://claude.ai/artifact/LcnLpvs9hN2kv6SgVE59a7 와 같은 식). 페이지 「지금 상태」의 합친 값은 두 채널 1건당 평균을 채팅 건수 비중으로 가중한다(9월: 케어파트너 1,576 · 케어아카데미 786).
- **은주 값을 못 받았으면 이 행을 쓰지 않는다** — 파일에서 센 봇완결률로 `해결률`을 채우지 말 것.
- ⚠️ **정의가 바뀐 회차면 `이 회차에 무슨 일이` 첫 줄에 그 사실을 쓴다**(18차 = 봇완결 판정 변경, [metrics.md](metrics.md)). 차트의 꺾임을 개선/악화로 오독하지 않게.
- 저장 후 **행 수 = (회차 수 × 2) + 기준선 2**인지 확인한다.

## 8-C. 4분기 페이지 갱신

페이지 구조(2026-10-08, 이 순서를 바꾸지 않는다):
`지금 상태`(채널별 표: 관여율·해결률·이탈률·KR2 + 합친 KR2 한 줄) → 📈 추이 DB → `측정 규칙` → `다음 회차에 할 일` → `살아있는 개선점`(📊 개선점 DB) → `최신 회차 상세`(접기) → `3분기 기록`

회차가 늘 때 하는 일은 **네 가지**다.

**1. 직전 회차 상세를 아카이브로 내린다.** 본문의 「최신 회차 상세」 토글 안 내용을 통째로 잘라 하위 페이지 「회차 기록 (4분기)」의 **맨 위**에 붙인다(최신이 위). 이 하위 페이지는 **19차 때 처음 만든다**(4분기 페이지 아래, `notion-create-pages` parent=page_id). 만든 뒤 이 문서에 주소를 적는다.
- 옮길 때 제목을 `# N차 점검 (YYYY-MM-DD) {toggle="true"}` 형식으로 바꾸고, **본문 전체를 탭 한 칸 들여쓴다**(들여쓰지 않으면 토글 밖으로 나온다).
- **본문에서 지우는 것과 아카이브에 붙이는 것을 같은 턴에 한다.** 지우기만 하고 붙이기를 잊으면 회차가 통째로 사라진다.

**2. 「최신 회차 상세」에 이번 회차를 넣는다.** 토글 제목은 `# N차 상세 (YYYY-MM-DD) {toggle="true"}`, 하위 소제목은 **네 개로 고정** — `## 분석 결과` / `## 이번 회차 발견` / `## 안 풀린 것 · 개선 확인된 것` / `## 개선점 추적 (N차 신규)`. **소제목을 늘리지 않는다.**
- `분석 결과` = 채널별 판정 등급 표 + 검증 줄 + `AI상담/*` 태그 분포. 채널을 한 표에 섞지 말고 채널별로 나눈다.
- `이번 회차 발견` = 최대 발견 1~3개를 수치·chatId와 함께. 봇 발화가 있으면 원문을 인용한다.
- `개선점 추적` = `개선점 / 배경 (왜) / 확인 방법 / 상태` 4열 표. **이번 회차 신규만**(기존 항목 경과는 DB가 관리).

**3. 「지금 상태」를 이번 회차로 갈아끼운다.** 제목의 회차·날짜, 채널별 표(관여율·해결률은 은주 값, 이탈률은 measure.py), 합친 KR2 한 줄. 해결률 옆 이탈률은 빼지 않는다.

**4. 「다음 회차에 할 일」을 새로 쓴다.** `먼저 볼 것`(5개 이내) / `계속 확인` / `이월·대기` 세 묶음.
- 🔴 **직전 회차 목록을 그대로 복사해 오지 말 것.** 항목마다 숫자를 **이번 회차 값으로 갈아끼우고**, 종결된 항목은 지운다(11차 사례 → past-cases.md).
- 미해결 전건은 DB가 관리한다. 여기엔 다 옮기지 않는다(이중 관리).
- `이월·대기` 마지막 줄에 항상 `DB에서 상태 = 미확인 을 걸러본다. 회차당 최소 1건은 결론 낼 것`을 남긴다.

## 지킬 것

- ⚠️ **본문에 회차 섹션을 쌓지 말 것.** 본문에 남는 회차 상세는 항상 최신 하나뿐이다(3분기에 1,037줄까지 쌓였던 전례).
- ⚠️ **상태 표를 페이지에 다시 만들지 말 것.** 상태는 DB에만 둔다. 표를 또 만들면 DB와 어긋난다.
- ⚠️ **원문자(①②③, ⓐⓑ)를 쓰지 말 것 — 은주 화면에서 안 보인다.** 판정 등급은 이름으로 부르고(`봇완결`·`정당 이관`·`놓침`·`이탈`), 자동화 여력은 `2-A`/`2-B`로 쓴다. 이월 행 본문에 3분기 원문 그대로 남은 원문자는 원문 보존이라 둔다.
- **강조를 아껴 쓴다.** 굵게는 문단·표 셀당 1개까지, 인용문(`>`)은 경고·검증처럼 층이 다른 정보에만.
- 🔴 **`<database>`·`<page>`·`<mention-page>` 태그를 지우지 말 것.** `replace_content`로 본문을 통째로 바꿀 때 📈 추이 DB · 📊 개선점 DB 두 줄(19차부터는 회차 기록 하위 페이지도)이 빠지면 **실제로 삭제된다.** 교체 전 `notion-fetch`로 현재 태그의 `url`·`data-source-url`을 그대로 복사해 둔다. 가능하면 `update_content`로 필요한 블록만 고친다.
- 페이지 표 수정 시 `update_content`의 `old_str`은 **들여쓰기까지 정확히** 맞아야 한다. HTML 주석(`<!-- -->`)은 마커로 쓰지 말 것(매칭 안 됨).
- 개인정보는 노션에도 옮기지 않는다(익명화).
- 노션에 넣을 문구는 은주에게 먼저 보여주고 "써줘"를 받은 뒤 쓴다.
