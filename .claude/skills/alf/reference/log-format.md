# 로그 누적과 아카이브 (진행순서 7번에서 읽는다)

`cs-triage/ALF_개선로그/최신_*.md`에 이번 회차를 추가한다. 파일 맨 위 **현황 요약**은 매번 덮어쓰고, 그 아래 **개선 이력**에 새 회차를 최신순으로 끼워넣는다.

## 출력 형식

```markdown
### {오늘 날짜} | {N}차 점검
- **분석 대상**: {파일명/건수, 어떤 유형 위주}
- **분모 산출**: 전체 N → alf발동 N → 봇완결(미배정) N
- **결과**: 완결률 x%(N/N) · 이탈률 x%(N건) / ⚠️ 없앨수있는이관 N (2-A n · 2-B n) / ✅ 정당이관 N / ❌ 놓침 N
- **잘 된 점**: ...
- **문제점**: (위반 규칙·오답·불필요 이관)
- **미해결 전건 점검**: (진행순서 5-1 표 — 확인 목록 전건. 사례 0건도 "N회째 이월"로 한 줄씩)
- **개선 액션**: → {수정한 규칙 파일}에 {무엇을} / 또는 "제안만, 미반영"
- **직전 대비**: (지난번 지적이 이번에 좋아졌나)
- **다음 점검 때 확인할 것**: (신규 위주 5~7개. 미해결 전건은 노션 DB가 관리)
```

- 정의가 바뀐 회차면 그 회차 섹션에 **`- **집계 정의 변경**:` 줄을 넣는다**(무엇이 어떻게, 과거와 비교 가능한지). [metrics.md](metrics.md)의 문단을 옮겨 쓰면 된다.
- **현황 요약 블록의 "주요 미해결 이슈"는 DB의 `미해소`·`부분 확인` 행과 어긋나면 안 된다.** 로그를 갱신할 때 DB 상태를 그대로 반영한다 — 둘이 다르면 어느 쪽이 맞는지 아무도 모르게 된다.

## 아카이브 (누적이 끝나면 자동 실행)

```bash
python3 cs-triage/archive_log.py --apply
```

- 본문에는 **최근 3회차만** 남고 그보다 오래된 회차 섹션은 같은 폴더의 `지난기록_*.md`로 내려간다. **두 파일 이름의 회차 범위도 스크립트가 자동으로 갱신한다**(`최신_11~13차.md` → `최신_12~14차.md`).
- **내용은 한 글자도 버리지 않고 옮기기만 한다.** 옮길 것이 없으면 아무것도 하지 않으므로 **매 회차 조건 없이 그냥 돌리면 된다.**
- 스크립트가 이동 전 유실 검증을 하고 `ALF_개선로그/최신.md.bak`을 남긴다. 실행 결과(유지/이동 섹션 수, 감소율)를 마무리 보고에 한 줄로 적는다.
- ⚠️ **현황 요약·봇 도큐먼트 현황·분석 절차는 건드리지 않는다** — 스크립트는 `## 🗂 개선 이력` 아래의 `###` 섹션만 다룬다. 미해결 이슈는 본문에 계속 남는다(은주 결정 2026-08-19).
