# 지표 — 분모·완결률·이탈률과 정의 변경 이력

숫자는 `measure.py` 출력에서만 가져온다. 손으로 세지 않는다.

```bash
python3 .claude/skills/alf/measure.py cs-triage/상담내역/*.xlsx --out <저장소 밖 폴더>
```

## 계산식 (2026-09-07 개정 — 두 지표는 항상 짝으로 본다)

```
분모   = alfTriggered = true                       ← 이탈을 빼지 않는다
봇완결 = 분모 중 상담원 미배정
완결률 = 봇완결 ÷ 분모

이탈   = 분모 중 미배정 + 마지막 발화가 봇의 번호 요구·리셋 멘트·질문인 건
         ← 2026-09-11 개정(행동 기준)
이탈률 = 이탈 ÷ 분모
```

회차 보고에는 **분모 산출 과정을 밝히고, 완결률과 이탈률을 한 줄에 붙여 쓴다** — 예:
`전체 220 → alf발동 209 → 봇완결(미배정) 136 = 65.1% / 이탈률 5.3%(11건)`

> 🔴 **완결률만 떼서 보고하지 말 것.** 이탈 건이 분자에 들어가므로 **이탈이 늘면 완결률이 같이 올라간다.** 이탈률을 옆에 붙여야 이 역방향이 잡힌다. 실제로 08-18은 완결률 50.4%→56.9%로 올랐는데 이탈률도 6.1%→8.0%로 같이 올랐다 — 완결률만 봤으면 "좋아진 주"로 넘어갔을 자리다.

**이탈 판정 정규식** (measure.py에 박혀 있다. 바꾸면 계열이 끊긴다)
```python
PHONE = r'전화번호를 (먼저 )?알려주시겠어요|전화번호를 다시'
RESET = r'어떤 도움이 필요하신가요|궁금하신 내용을 말씀해 주시면'
ASK   = r'\?|과정을 말씀해 주세요'      # 검사 전에 URL(https?://\S+)을 지운다
CLOSE = r'더 도와드릴 것이 있을까요|다른 도움이 필요하신|궁금하신 점|궁금한 점'
# 미배정 & 마지막 발화 personType=='bot' 에 대해:
#   PHONE 또는 RESET 이면 이탈 / 아니면 ASK 이고 CLOSE 가 아니면 이탈
```
⚠️ **한계**: 답을 다 주고 끝에 `CLOSE`가 아닌 질문을 붙인 건도 이탈로 잡힌다(15차 18건 중 3~4건). 숫자는 15차와 같은 잣대라 계열은 유지되지만, 이탈 건을 근거로 쓸 때는 CSV의 `마지막봇발화`를 눈으로 확인한다.

# 집계 정의 변경 이력

지표 정의가 바뀌면 **그 회차 보고에 무엇이 어떻게 바뀌었는지 반드시 적는다.** 안 적으면 다음 사람(또는 다음 회차의 나)이 계열이 끊긴 걸 모르고 그냥 빼서 비교한다.

## 2026-09-11 개정 (15차부터 적용) — 은주 결정

| | 구 (~14차) | 신 (15차~) |
|---|---|---|
| 이탈 | `AI상담/고객이탈*` 태그 | **행동 기준** — 상담원 미배정 + 마지막 발화가 봇이고, 그 발화가 번호 요구·리셋 멘트·물음표 질문인 건 (URL 속 물음표, "더 도와드릴 것이 있을까요" 같은 마무리 질문은 제외) |
| 놓침 | `AI상담/오안내`·`이관안함`·`안내안함` 태그 | **대화를 읽고 판정** (태그가 있으면 참고만) — 등급 위에 겹쳐 표시하고 6개 시트에는 유형 분류로 넣는다 |
| `AI/상담완료`·`AI/상담원이관` | 워크플로우 정상 상태 태그 | **9월부터 안 붙인다.** 알프 응대 + 미배정 = 알프 상담 완료, 배정 = 상담원 이관. 0건이어도 이상 신호가 아니다 |

**왜 바꿨나**
- 9월부터 `AI/*` 태그를 폐지했고(은주), 15차 배치엔 `AI상담/고객이탈`이 0건 · `AI상담/*` 전체 6건뿐이라 태그로 이탈·놓침을 잴 수 없었다.

**감수한 것**
- 행동 기준은 태그(사람이 골라 붙인 부분집합)보다 **구조적으로 높다** — 15차 15.8% vs 14차 태그 3.7%. **14차 이하 이탈률과 이어 읽지 않는다.**
- export 직전 새벽에 시작된 상담은 아직 진행 중일 수 있다 — 마지막 날짜 건은 표시해 둔다.

**15차 보고에 넣은 문단**:
> 이번 회차부터 이탈·놓침을 세는 방법이 바뀌었다. 이탈은 `AI상담/고객이탈` 태그 대신 봇의 번호 요구·리셋 멘트·질문으로 끝난 미배정 건(행동 기준)으로, 놓침은 태그 대신 대화 판정으로 센다. 행동 기준 이탈률은 태그 기준보다 구조적으로 높으므로 **14차 이하 이탈률과 직접 비교하지 않는다.**

## 2026-09-07 개정 (14차부터 적용) — 은주 결정

| | 구 정의 (~13차) | 신 정의 (14차~) |
|---|---|---|
| 봇완결 판정 | `manager 발화 0개` (Message data 시트) | **`상담원 미배정`** (`assigneeId`·`firstAssigneeId`·`managerIds` 전부 공란) |
| 분모 | alf발동 − 이탈 | **alf발동** (이탈을 빼지 않음) |
| 이탈 처리 | △ 등급으로 완결에서 제외 | **완결에 포함**하고, **이탈률을 별도 지표로 분리** |
| 등급 | ✅ / ⚠️ / ❌ / △이탈 / 🚫제외 | ✅ / ⚠️ / ❌ / 🚫제외 (△ 폐지) |

**왜 바꿨나**
- `AI/상담완료` 태그는 미배정 건의 87~96%에만 붙어 있었다(사람·워크플로우가 붙여서 샌다). 배정 여부는 시스템 값이라 안 샌다.
- `미배정`과 `manager 발화 0개`는 6회차 전수 대조에서 **완전히 같은 답**을 냈다. 더 단순한 쪽을 택했다.
- 이탈을 완결에 섞는 대신 **이탈률을 따로 세워** 봇 이탈 문제를 독립 지표로 추적한다.

**감수한 것 (알고 택함)**
- 이탈 건이 분자에 들어가므로 **이탈이 늘면 완결률도 올라간다.** → 그래서 **완결률·이탈률을 항상 한 줄에 붙여 보고**하는 것으로 막는다. 이 짝을 깨면 정의가 무너진다.

**과거 회차는 재계산하지 않았다** (은주 결정). 참고용으로 신 정의 재계산 값만 아래에 남긴다 — **기록된 공식 계열은 여전히 구 정의다.**

|---|---|---|---|---|---|---|

**14차 보고에 넣을 것** — 로그·노션 양쪽에 이 문단을 쓴다:
> 이번 회차부터 집계 정의가 바뀌었다. 봇완결 판정이 `manager 발화 0개` → `상담원 미배정`으로, 분모가 `alf발동 − 이탈` → `alf발동`으로 바뀌었고, 이탈은 완결에 포함하되 **이탈률**로 따로 뽑는다. 신 정의는 구 정의보다 구조적으로 2~7%p 높으므로 **13차 이하 숫자와 직접 비교하지 않는다.**

## 과거 회차 비교 시 주의

- **5~9차는 재계산된 계열을 쓴다.** 2026-08-06에 `alfTriggered` 기준으로 전수 재계산했다(27.5 / 39.6 / 39.5 / 39.5 / 46.3%). 그 이전에 기록된 20/34/34/37/36% 계열은 폐기됐다.
- 🔴 **13차까지의 기록된 완결률은 「구 정의」다**(이탈 제외 분모 · manager 발화 기준). **14차 이후 숫자를 13차 이하와 그냥 빼서 비교하면 안 된다** — 신 정의가 구조적으로 2~7%p 높게 나온다. 비교가 필요하면 위 신 정의 재계산 표를 쓰고, 어느 계열인지 반드시 밝힌다.
