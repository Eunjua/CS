# 상황 지도 운영 — 역할 지표 · 새 유형 · 논의

ALF 재설계(`cs-triage/ALF_설계/`)의 상황 지도를 매주 실제 상담으로 키우는 절차. 지도가 "어떤 문의를 AI가, 어떤 문의를 상담원이 맡나"의 기준이다.

## 목차
- A. 역할 지표 — 분석 세션 3-1
- B. 새 유형 정리·후보 등록 — 분석 세션 3-2
- C. 논의 모드 — 은주가 따로 연 세션
- D. 반영한 날 표시 — 개선 작업 모드 12번

파일: `역할지표.py`(추출·집계·논의 목록·페이지) · `분류지침.md` · `상황지도.md`(정식 줄 + 「후보」 표 + 결정 기록) · `역할추이.json`(숫자만) · `논의/`(gitignore) · 페이지 https://claude.ai/artifact/Ak5u5ZBxjqRkoUTWR5gzSf

---

## A. 역할 지표 (분석 세션 3-1)

이 주 export **두 채널을 같이** 넣는다 — 아카데미 문의의 60%가 케어파트너 채널로 들어온다. 채널별 숫자는 스크립트가 따로 낸다.

```bash
D=cs-triage/ALF_설계; OUT=<저장소 밖 폴더>
python3 $D/역할지표.py extract 채널톡/<이번 주 파일들>.xlsx --out $OUT
```
1. batch 파일마다 서브에이전트에 `분류지침.md`대로 코드를 붙이게 한다(batch 3개면 3개 동시). 결과를 `$OUT/codes.tsv`로 합치고, 줄 수 = 분류 대상 건수인지 확인한다.
2. `python3 $D/역할지표.py aggregate --out $OUT --note "<이번 주에 바꾼 것 한 줄>"` → `역할추이.json`에 이 주가 들어간다(같은 주는 덮어씀).
3. 세 숫자를 같이 본다: **지금 상담원 %**(상담원이 고객에게 말한 상담) · **설계 상담원 %**(지도에서 상담원 담당) · **AI 몫인데 상담원이 받은 건**(줄여 갈 숫자). 상담원 담당 문의가 몰리면(예: 본인인증) 지금 %가 올라도 봇 탓이 아니다.
4. 5번 종합에 세 숫자(기준선 평균 대비)와 AI 몫인데 상담원이 많은 단계 상위 3을 쓴다.

기준선: 10/5~10/25 3주, 재설계 반영 전. 전화 상담은 기준선과 맞추려고 뺀다. 토큰이 많이 드는 단계다(571건에 약 56만) — 은주가 줄이자고 하면 표본 분류로 바꿀지 묻는다.

## B. 새 유형 정리·후보 등록 (분석 세션 3-2)

1. `python3 $D/역할지표.py discuss --out $OUT` → `논의/논의목록_<export>.md`. 새 유형(NEW·후보 코드) 묶음과 AI 몫인데 상담원이 많이 받은 줄 상위 5, 각각 고객 말·상담원 답 표본이 들어간다.
2. **새 유형을 묶는다.** 문구만 다르고 같은 상황인 NEW는 하나로 합친다. 기존 정식 줄로 볼 수 있으면 그 줄로 보낸다. 합치거나 보낸 항목은 `결정:` 줄에 "C9로 합침"처럼 바로 적어 논의 모드에서 다시 잡히지 않게 한다.
3. **`상황지도.md` 「후보」 표에 바로 올린다** — 건수와 관계없이. 코드는 그 여정 글자의 다음 번호(예: C8). 칸: 코드 · 단계 · 상황 · 고객 표현 · 처음 본 주 · 누적 건수 · 제안 담당 · 들어갈 곳 제안 · 확인할 것. 이미 후보에 있으면 누적 건수만 더한다.
4. **논의 목록의 `제안` 줄을 채운다.** 상담원 답이 AI 답의 재료다.
   - 새 유형: 담당(AI 안내 / AI 조회 / 상담원) · 들어갈 곳(FAQ·아티클·엑셀·태스크) · 은주에게 확인할 사실
   - AI 몫인데 상담원 줄: 왜 AI가 못 끝냈나(지식 없음 / 매칭 실패 / 태스크가 연결로 보냄 / 고객이 상담원 요구) · 무엇을 고치나
5. **분석 세션에서는 논의하지 않는다**(2026-11-02 은주: "논의는 따로"). 11번 마무리에 "논의 목록 N건 — 따로 시간 날 때 `알프 논의하자`라고 불러 주세요"를 붙인다.
6. 페이지를 다시 올린다(SKILL 8-1과 같음, 아래 「페이지 다시 올리기」).

## C. 논의 모드 — "알프 논의하자"

새 세션이라 분석 때 대화는 없다. 파일에서 다시 세운다.

1. `cs-triage/ALF_설계/논의/`에서 `결정:` 줄이 빈 항목을 모은다(지난주 것 포함). 오래된 주부터가 아니라 **건수 많은 순**.
2. 항목마다 짧게 보여 준다: 상황 · 건수 · 고객 말 1개 · 상담원 답 1개 · 제안 · 확인할 것. 은주가 정하면 다음 항목으로. "다음 주에 보자"면 그대로 둔다.
3. 정한 것 반영:
   - 담당이 정해진 새 유형 → 「후보」 표에서 빼고 해당 단계 표에 정식 줄로 옮긴다(처리 방식 칸에 `안내`/`조회`/`사람`).
   - 답 문구·정책 → 결정 기록 표에 한 줄.
   - 반영할 일(FAQ 문구 · 아티클 · 태스크 수정 요청문 · 테스트 문장) → 개선로그 최신 회차 「개선 액션」 **그리고** 📊 개선점 DB에 `미확인` 행(회차 = 최신 회차, 개선점 앞에 `[논의]`). 둘 다 있어야 개선 작업 모드 0번이 목록을 맞추고 12번이 조치 칸을 채운다. 노션은 초안을 보여 주고 "써줘"를 받은 뒤 쓴다.
   - 논의 목록 그 항목의 `결정:` 줄에 결론.
4. 끝나면 페이지를 다시 올린다(아래 「페이지 다시 올리기」). 정한 것 요약 + "GitHub에 올릴까요?".

지도를 고치는 판단(담당·문구)은 은주가 한다. Claude는 제안하고 기록한다.

## D. 반영한 날 표시 (개선 작업 모드 12번)

재설계 단계를 채널톡에 반영했거나 논의에서 정한 줄을 반영했으면 `역할추이.json`을 고친다.
- `status`의 그 단계 값 (예: `"결제": "채널톡 반영 11/4"`)
- `changes`에 `{"date": "2026-11-04", "stage": "결제", "short": "결제 교체", "what": "새 FAQ 10개·아티클 반영", "mark": true}`
- 페이지를 다시 올린다(아래) — 추이 그래프에 점선이 찍혀 전후가 보인다.
