**두 잣대를 구분한다.** 말투·태도·이관 판단 = `ALF_rules/` 7종 + 구분기준 통합본, 사실관계·정답 여부 = `ALF_docs/` + `ALF_FAQ/`. 봇 답이 "불친절"인지 "사실이 틀림"인지를 이 둘로 갈라 판정한다.

**규칙은 2000자 제한.** `ALF_rules/*.md` 한 파일은 채널톡 한 규칙으로 들어가며 **2000자(문자·숫자·특수문자·공백 전부 포함)**를 넘으면 안 된다. 수정·압축 시 `python3 -c "print(len(open(...).read()))"`로 글자수를 확인한다. **멘트는 규칙에 넣지 말고 "언제 상담을 열지" 조건만** 쓴다(멘트+상담열기를 함께 넣으면 상담 열기가 실패). 연결 멘트는 자동 전송되나 **사과는 미포함**(사과는 담당자가 응대 시 전함).

## 지식 소스 — 둘이다

🔴 **봇의 지식 소스는 docs와 채널톡 FAQ 둘이다.** **"docs에도 FAQ에도 없어야 공백"이다.** 같은 주제가 양쪽에 다르게 적혀 있으면 봇이 어느 쪽을 꺼내느냐에 따라 답이 갈린다 — 회차마다 따로 점검한다(진행순서 5-3).

### `cs-triage/ALF_docs/`
**봇이 실제 참고하는 지식 도큐먼트.** 봇 답변의 **사실관계가 맞는지**, **도큐먼트에 항목이 아예 없어서 답을 못 한 건지(②-A-② 공백)**를 판정하는 잣대. 비어 있으면 사실관계 판정은 보류하고 "도큐먼트 미등록"이라 표시한다.
- 상위(`ALF_docs/*.md`) = **공통 정책**(수강·시험·발급·신청·자격증 안내)
- `ALF_docs/자격증상세/*.md` = **과목별 상세**(소개·주요업무·활용분야·상세페이지 URL 등). "이 자격증 따면 무슨 일 해요/어디서 써요/강의 어디서 들어요" 류 문의의 사실 잣대.
- **레포가 원본이므로** 파일을 고친 뒤 **채널톡 등록까지 확인**한다(11차 최대 교훈).

### `cs-triage/ALF_FAQ/FAQ_목록.md`
**FAQ 사본. docs와 나란히 봇이 참고하는 두 번째 지식 소스다.** ⚠️ **원본은 채널톡이고 은주가 직접 고친다** — 레포 파일을 고쳐도 봇에 반영되지 않는다(2026-08-25 결정).
- **간단하고 답이 하나로 떨어지는 질문은 FAQ가 더 잘 답한다** — 질문·답 쌍이라 고객 문장과 바로 매칭되기 때문. 조건에 따라 답이 갈리는 것은 docs가 맡는다.
- ⚠️ **`alfUsedCount`를 믿지 말 것.** 집계가 안 되는 필드다(→ [past-cases.md](past-cases.md)).
- **FAQ 수정은 파일로 하지 않는다.** 고칠 것이 있으면 **"무엇을 어떻게 고쳐라"를 은주에게 글로 전달**하고, 은주가 채널톡에서 직접 반영한다. 업로드용 xlsx를 만들지 말 것(2026-08-25 은주 결정).
- 이 사본은 오래되기 쉽다. 가끔 export를 받아 표를 갱신하고, **FAQ 내용을 판정 근거로 쓸 때는 사본이 언제 것인지 먼저 본다.**
- ⚠️ **"고쳤다"는 기록을 근거로 쓰지 말 것.** 원본을 열어 확인한다(→ past-cases.md).

## 흐름 층의 원본 — `cs-triage/ALF_task/통합상담_*.json`

채널톡 ALF 태스크 export. 파일명은 `통합상담_YYYY-MM-DD_HHMM.json`(export 시각)이고, 이름순 마지막 파일이 최신이다.
- 읽을 곳: `task.nodes`(id·name·type·steps/code/message·next 분기) · `task.memorySchema` · `task.trigger`.
- ⚠️ 코드 노드에 **사내 API 키·배송 시트 토큰이 평문으로 들어 있다** — 출력할 때 `KEY`·`TOKEN` 값은 항상 `***`로 가린다. 이 폴더는 `.gitignore` 대상이라 커밋하지 않는다(공개 저장소).
- **직전 날짜 파일이 있으면 노드별로 비교**해 바뀐 노드·문구·분기를 뽑는다 → 로그에 「태스크 변경」으로 기록하고, 상담 판정을 변경 전후로 가른다. 파일이 하나뿐이면 비교는 건너뛴다.
- 은주가 새 export를 주면 `ALF_task/통합상담_{날짜}_{HHMM}.json`으로 옮긴다(파일 수정 시각 기준, 덮어쓰지 않는다). 직전 파일과 노드별로 비교해 **의도한 변경 외에 바뀐 노드가 없는지** 반드시 확인한다(→ past-cases.md). 변경 이력 DB 행은 제목·대상 노드로 구분한다(계획할 때 쓰는 임시 이름은 칸으로 만들지 않는다). 옮긴 뒤 Downloads 원본은 지우도록 안내한다.
- 📒 **태스크 관리 페이지**: https://app.notion.com/p/3d872773c3638146915afe4451625b2b — 수정 절차·파일 목록·**🗂 태스크 변경 이력 DB**(수정 1건 = 1행). 비교 결과는 이 DB에 기록하고, 분석 때는 `반영 일시`로 상담을 변경 전후로 가른다.
