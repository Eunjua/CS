# 규칙이 생긴 사례 — 규칙을 바꿀지 판단할 때만 읽는다

SKILL.md의 원칙은 전부 실제로 틀린 적이 있어서 생겼다. 원칙을 고치거나 예외를 두려 할 때 여기를 먼저 본다. **"그때는 이래서 틀렸다"를 모르고 고치면 같은 자리에서 다시 틀린다.**

## 태스크와 규칙을 헷갈린 것 — 11차

봇이 번호를 먼저 요구하는 문제를 **규칙을 두 번((자)→(하)) 고치고도** 그대로였다. 번호 선요구는 규칙이 아니라 **태스크에 박힌 흐름**이었기 때문이다.
→ **동작(언제 무엇을 부르는가)은 태스크 영역.** 흐름 문제로 판정하면 규칙 개정을 제안하지 않고 `ALF_task/` 최신 파일에서 노드를 찾는다.

## "docs에 없음 = 공백"으로 단정한 것 — 11차까지

11차까지는 docs만 보고 판정해서 **"docs에 없으니 지식 공백"으로 잘못 단정한 사례가 여럿** 있었다. 내일배움카드는 2026-05-23부터 FAQ에 있었는데 docs 공백으로 봤다.
→ **"docs에도 FAQ에도 없어야 공백"이다.**

11차 `6a7bfbdd`는 반대 사례다 — 시험 중 이탈 FAQ가 **있는데도** 봇이 번호부터 물어 도달하지 못했다. 이건 공백이 아니라 **도달 실패**다.

## 한 회차 0건을 "해소"로 읽은 것 — 8차

8차에 "docs 연동 해결"로 닫았다가 **9·10차에 재발해 판정을 철회**했다. 6차 배송현황 docs도 같은 식으로 뒤집혔다.
→ **`완료/해소`는 2회 연속 재발 없음일 때만.** 한 회차 0건은 "재발 없음"이지 "해소"가 아니다. 그리고 **사례가 0건이면 해소가 아니라 검증 불가**다 — 폭언 규칙은 사례가 없어 4회째 판정 불가지, 해결된 게 아니다.
→ 뒤집힌 전례가 있어서 **DB 행을 지우지 않는다.** 해소된 것도 이력으로 남긴다.

## 지표 하나만 보고 반대로 읽을 뻔한 것 — 10차

"봇 첫 발화 번호선요구 23.5%→2.5%"를 개선으로 볼 뻔했는데, 앞에 접수 멘트가 끼면서 번호 요구가 **둘째 발화로 밀린 지표 착시**였다. 실질 지표(답변보다 먼저 번호만 요구)는 65%→63%로 제자리.
→ **개선으로 보이면 다른 각도의 지표로 한 번 더 재고, 정의를 결과에 명시한다.**

같은 이유로 완결률과 이탈률은 항상 붙여 본다 — 08-18은 완결률이 50.4%→56.9%로 올랐는데 이탈률도 6.1%→8.0%로 같이 올랐다. 완결률만 봤으면 "좋아진 주"로 넘어갔을 자리다.

## docs가 봇에게 틀린 지시를 하고 있던 것 — 10차

지금까진 "봇이 docs를 따르나"만 봤는데, 10차에 **반대 방향이 2건** 나왔다(배송현황 조회·기출문제) — **제품에 기능이 생겼는데 docs가 낡아서** docs가 봇에게 틀린 지시를 하고 있었다. 봇이 맞게 답하거나(배송) 문의 사례가 없으면(기출) 분석으로는 영원히 안 잡힌다. **둘 다 은주가 docs를 직접 읽다 발견했다.**
→ 회차마다 은주에게 **"지난 회차 이후 제품에 붙은 기능이나 바뀐 정책이 있나요?"**를 묻는다. 이 질문이 가장 확실하다.

## 태그로 AI 관여를 판정한 것 — 9차

9차에 태그로 판정해 보니 **ALF가 실제로 응대했는데(봇 발화 최대 19건) 태그만 안 붙은 건이 11건** 있었다. 태그는 사람이 붙이는 것이라 누락된다.
→ `alfTriggered`는 시스템이 찍으므로 신뢰할 수 있다.

9차(2026-08-06)엔 161건 중 **12건이 ALF 미발동**이었는데 이를 걸러내지 않아 **봇완결률이 36%(실제 46.3%)로 과소 보고**되기도 했다. 상담원 발화가 있다는 이유로 "이관"으로 세면 봇이 등장할 기회조차 없던 건까지 자동화 여력에 들어간다.

`AI/상담완료` 태그도 같은 문제였다 — 미배정 건의 **87~96%에만** 붙어 있었다(8/31: 136건 중 122건). 나머지는 `AI` 부모태그만 달렸거나 export 시점에 `state=initial`이라 아직 안 붙은 것이다.
→ **태그는 사람·워크플로우가 붙여서 새고, 배정 여부는 시스템 값이라 안 샌다.**

## 미해결 항목이 조용히 사라진 것 — 2~10차 전수 점검에서 발견

이번 배치에서 새로 발견한 것만 보고하다 보니 지난 회차의 `부분 확인`·`계속 추적`·`미확인`이 조용히 사라졌다. 전수 점검했더니 **결과 칸이 빈 채 추적이 끊긴 항목이 5건** 있었다(봇 제공목록 동기화 · 취업 과장 방지 규칙 · docs 미반영 6종 · 교재 링크 후속 · 운영시간외 멘트 설정). 회차마다 "다음 점검 때 확인할 것"을 5~7개로 새로 쓰다 보니 급한 신규 이슈가 오래된 항목을 밀어낸 것이다.
→ **진행순서 2-1에서 미해결 전건을 먼저 뽑고, 5-1에서 그 전건에 결과를 적는다. 빈칸으로 두지 않는다.**

## FAQ에서 데인 것들

- ⚠️ **`alfUsedCount`를 믿지 말 것.** 2026-08-19 시점 15개 전부 0이었으나 답변 문구를 봇 발화와 대조하니 **11개가 실제 사용 중**이었다. 집계가 안 되는 필드다.
- ⚠️ **"고쳤다"는 기록을 근거로 쓰지 말 것.** 08-19에 나이 제한 충돌을 "해소했다"고 요약 문서에 적었으나 **원본은 안 고쳐져 있었다**(08-25 발견). 원본을 열어 확인한다.
- **FAQ ↔ docs 충돌은 docs만 봐서는 안 보인다.** 2026-08-19 발견: FAQ 「수강 어떻게 들어요?」는 안드로이드 앱 링크만 있고, docs 수강정책 §1에는 **"아이폰은 앱 설치 불가 → 케어파트너 사이트로 접속"**과 PC 수강이 있었다. 봇이 FAQ를 꺼내면 **아이폰 고객에게 안 되는 방법을 안내**한다. 금액도 위험하다 — 재수강료 95,000원은 FAQ에만, 발급비 93,000원은 docs에만 있었다.

## 태스크 export에 요청 외 변경이 섞여 온 것 — 2026-09-11

배송 만료 경로 수정 export에 **요청하지 않은 변경 2건**(환불 경로·복수 과정 선택)이 함께 들어 있었다.
→ 새 export를 받으면 직전 파일과 노드별로 비교해 **의도한 변경 외에 바뀐 노드가 없는지** 반드시 확인한다.

## 노션 페이지가 불어난 것 — 11차 정리 전

- 본문에 회차 서술 11개(2~10차, **1,037줄**)가 쌓여 있어 2026-08-19에 하위 페이지로 내렸다.
- 회차 상세 소제목이 **회차당 8개까지** 늘어 뭐가 중요한지 안 보였다 → 네 개로 고정.
- **굵게 493개·인용문 56개**라 강조가 강조 역할을 못 했다 → 굵게는 문단·표 셀당 1개까지.
