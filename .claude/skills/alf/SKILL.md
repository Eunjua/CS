# ALF 개선 스킬 — 상담 분석 → 규칙 개선 → 로그 누적 사이클

케어아카데미 AI 상담봇(ALF)의 응대를 **실제 상담 내역으로 점검하고, 규칙을 고치고, 개선 이력을 누적**하는 반복 사이클. 사용자(은주, CX Manager)가 `cs-triage/상담내역/`에 파일을 올리고 부르면 아래 절차를 끝까지 돈다.

## 핵심 원칙
- **새 파일만 분석한다.** `상담내역/` 바로 아래의 파일만 본다. `처리완료/` 안은 이미 분석한 것이므로 건드리지 않는다.
- **상담 파일은 엑셀(.xlsx)이다.** 파이썬(`mcp__plugin_oh-my-claudecode_t__python_repl` 또는 Bash의 `python3` + `openpyxl`/`pandas`)으로 읽어 대화 내용을 추출한다. 컬럼 구조가 처음 보는 형태면 먼저 상단 몇 행을 출력해 구조를 파악한 뒤 분석한다.
- **두 잣대를 구분한다.** **말투·태도·이관 판단 = `ALF_rules/` 7종 + 구분기준 통합본**, **사실관계·정답 여부 = `ALF_docs/` 봇 지식 도큐먼트**. 봇 답이 "불친절"인지 "사실이 틀림"인지를 이 둘로 갈라 판정한다.
- **개선은 제안하고 승인받는다.** 규칙 파일(`ALF_rules/*.md`) 수정은 사용자 비개발자임을 감안해 "이렇게 고칠게요" 먼저 보여주고 승인 후 반영.
- **이력은 무조건 남긴다.** 한 번 돌 때마다 ① `ALF_개선로그.md`(정본)에 날짜·문제·액션·다음 확인사항을 누적하고, ② **노션 추적표**(개선점·확인방법·다음결과)에 반영하고, ③ **기준표 통합본 엑셀 `분석` 시트**에 건별 분류를 이어 붙인다. "지난번 고친 게 이번엔 좋아졌나"를 추적하는 게 이 스킬의 핵심 가치다.
- **봇 발화 텍스트가 없을 수 있다.** export에 ALF(봇) 메시지가 빠지고 user·manager만 있는 경우, 봇 말투·정확도 직접 채점은 보류하고 **이관 적정성·도큐먼트 커버리지** 중심으로 판정한다(어떤 문의를 봇이 혼자 끝냈나/사람에게 넘겼나, 넘긴 건의 사람 답이 표준 복붙이면 "없앨 수 있는 이관"). 이 한계를 결과에 명시한다.
- **규칙은 2000자 제한.** `ALF_rules/*.md` 한 파일은 채널톡 한 규칙으로 들어가며 **2000자(문자·숫자·특수문자·공백 전부 포함)**를 넘으면 안 된다. 수정·압축 시 `python3 -c "print(len(open(...).read()))"`로 글자수를 확인한다. **멘트는 규칙에 넣지 말고 "언제 상담을 열지" 조건만** 쓴다(멘트+상담열기를 함께 넣으면 상담 열기가 실패). 연결 멘트는 자동 전송되나 **사과는 미포함**(사과는 담당자가 응대 시 전함).

## 잣대가 되는 파일 (분석 전 반드시 로드)
- `cs-triage/케어아카데미_AI사람_구분기준_통합본.md` — 유형 코드(①, ②-A, ②-A-①/②, ②-B, ③실작업/③감정/③기술)와 2-0 레드라인 게이트
- `cs-triage/ALF_rules/` 7종:
  - `CX 톤앤매너.md`
  - `고객 정보 확인 규칙.md`
  - `상담원 연결 규칙.md`
  - `답변 정확도 규칙.md`
  - `공감 표현.md`
  - `금지 표현 규칙.md`
  - `고객 폭언, 욕설 대응.md`
- `cs-triage/ALF_docs/` — **봇이 실제 참고하는 지식 도큐먼트**. 봇 답변의 **사실관계가 맞는지**, **도큐먼트에 항목이 아예 없어서 답을 못 한 건지(②-A-② 공백)**를 판정하는 잣대. 비어 있으면 사실관계 판정은 보류하고 "도큐먼트 미등록"이라 표시한다.
  - 상위(`ALF_docs/*.md`) = **공통 정책**(수강·시험·발급·신청·자격증 안내)
  - `ALF_docs/자격증상세/*.md` = **과목별 상세**(소개·주요업무·활용분야·상세페이지 URL 등). "이 자격증 따면 무슨 일 해요/어디서 써요/강의 어디서 들어요" 류 문의의 사실 잣대.
- `cs-triage/ALF_개선로그.md` — 직전까지의 개선 이력, "도큐먼트 현황", "다음 점검 때 확인할 것"
- **노션 추적표** — 개선점·확인방법·다음결과를 회차별로 누적하는 외부 페이지(로그의 요약·추적용). 분석 시작 시 "다음 분석 결과" 빈칸을 함께 확인. URL: https://app.notion.com/p/38b72773c363801db00cd81a068ffdaf (Notion MCP `notion-fetch`/`notion-update-page` 사용)

## 진행 순서

1. **새 상담 파일 수집.** `cs-triage/상담내역/` 바로 아래(하위 `처리완료/` 제외)의 파일을 모두 찾는다.
   - 파일이 없으면: "상담내역 폴더에 새 파일이 없어요. 분석할 상담을 `cs-triage/상담내역/`에 올려주세요"라고 안내하고 멈춘다.
   - 있으면 몇 건/어떤 파일인지 먼저 알린다.

2. **잣대 로드.** 위 "잣대가 되는 파일" 중 구분기준 통합본 2장(판단기준)과 ALF_rules 7종, 그리고 ALF_개선로그.md의 **"다음 점검 때 확인할 것"** 항목을 읽는다. 직전에 고친 규칙이 이번 상담에서 실제로 개선됐는지 우선 확인 대상으로 삼는다.

3. **상담 한 건씩 판정.** 각 상담(또는 각 대화)에 대해:
   - **유형 분류**: ①/②-A(-①/②)/②-B/③실작업/③감정/③기술 중 무엇인가. 2-0 레드라인(금전·개인정보·신원·재량 / 화남·불신·전화고집·디지털취약) 먼저 적용.
   - **ALF 응대 판정**: 봇이 어떻게 답했나 → 7종 규칙 기준으로 ✅잘함 / ⚠️아쉬움 / ❌위반. 위반 시 **어느 규칙의 어느 항목**을 어겼는지 명시.
   - **사람 이관 적정성**: 사람한테 넘긴 건이면 정말 사람이 필요했나(③), 아니면 봇이 풀 수 있었나(②). 봇이 풀 수 있었는데 이관했으면 "없앨 수 있는 이관"으로 표시.
   - **사실관계 판정 (ALF_docs 기준)**: 봇 답을 `ALF_docs/`의 해당 도큐먼트와 대조한다.
     - 도큐먼트와 다르게 답함 → ❌오답 (어느 도큐먼트의 무엇과 어긋나는지 명시)
     - 도큐먼트에 항목이 아예 없어서 못 답함/이관 → ②-A-② **도큐먼트 공백** (어느 도큐먼트에 무엇을 추가해야 하는지)
     - `ALF_docs/`가 비어 있으면 사실관계는 "도큐먼트 미등록"으로 보류.

4. **엑셀 분석 시트 누적.** 판정한 배치를 건별로 `cs-triage/케어아카데미_AI사람_기준표_통합본.xlsx`의 **`분석` 시트**(구 `이관사유_상세`, 같은 시트)에 이어 붙인다.
   - 시트명은 유니코드 정규화(NFC/NFD) 차이가 있을 수 있으니 `unicodedata.normalize('NFC', s)`로 매칭해 찾는다. 시트명이 바뀌어 있으면 그 시트를 쓴다.
   - 컬럼: **A 순번**(기존 마지막 순번 이어서) · **B id** · **C url** · **D 태그(원본)** · **E 분류태그**(원본 `아카데미_` 태그에서 접두어 제거, 없으면 빈칸) · **F 5단계 분류**(①/②-A/②-B/③실작업/③감정/③기술) · **G 이관 사유**(한 줄) · **I 없앨수있는이관**(②=Y / ③=N / ①=-).
   - **H 열(은주 확인/이관 이유)은 절대 건드리지 않는다**(은주 수기 확인용, 항상 공백으로 남김).
   - id·url·태그는 UserChat 시트에서 추출하고, F·G·I는 step 3 판정 결과를 쓴다. (AI/상담완료=봇 완결 → ① / I="-", 이관건은 ②=Y·③=N)
   - openpyxl로 append 전 **원본을 한 번 백업**(스크래치패드 복사)하고 저장한다. 기존 행은 보존(append-only).

4-1. **유형별 집계시트에 이번 배치 열 추가.** 같은 엑셀의 **6개 집계시트**(`집계_①현재AI` · `집계_②A즉시자동화` · `집계_②B시스템연동` · `집계_③실작업` · `집계_③감정전화` · `집계_③기술오류`)에 이번 배치를 **새 열(배치=export 파일명, 예 `20260625_0701`)**로 이어 붙인다.
   - **건별 실제 판정으로 배정**: 완결(AI/상담완료)=`①현재AI` / 이관건은 세부태그의 대분류로. 그래서 **같은 세부태그(예 일자리)가 완결분은 ①시트, 이관분은 ②-A시트에 각각** 나뉘어 들어간다. 6개 시트 건수 합 = 그 배치 총 상담수(검증).
   - **세부태그→대분류 매핑**: `분석` 시트에서 학습(각 태그의 ① 제외 이관 최빈 대분류)한다. 명백한 기술장애(`수강/동영상`·"소리/영상 안 나옴") = ③기술오류, 감정·전화고집 발화 = ③감정전화로 보정. 봇 발화 없으면 이 세분은 근사임을 밝힌다.
   - 각 시트: **A열 유형(세부태그)** · **B열~ 배치별 건수**(최신 배치 건수 내림차순 정렬) · 맨 아래 **합계행**. **새 유형은 해당 시트 맨 아래 새 행**으로 추가.
   - 배치 상담수는 **파일명 시작일(YYYYMMDD) 이후**로 일관 필터(과거 배치와 겹치는 오래된 상담 제외).

5. **분석 결과 표로 정리.** 사용자에게 보여준다.
   ```
   | # | 유형 | ALF 응대 | 판정 | 문제 / 위반 규칙 | 개선 액션 |
   ```
   - 끝에 **종합**: 이번 배치에서 가장 반복된 문제 1~2개, 직전 점검 대비 좋아졌는지/그대로인지.

6. **개선 제안.** 고칠 게 있으면 문제 유형에 맞는 곳을 짚는다:
   - **말투·태도·이관 문제** → 어느 `ALF_rules/*.md`(또는 구분기준 통합본)를 어떻게 고칠지.
   - **사실관계 오답·도큐먼트 공백** → 어느 `ALF_docs/` 도큐먼트에 무엇을 추가/수정할지. (단, ALF_docs 도큐먼트의 실제 수정·반영은 봇 운영 쪽 작업일 수 있으므로 "도큐먼트에 이걸 넣어야 함"을 제안으로 남기고, 사용자가 원하면 파일에 반영.)
   - **승인받은 것만** 실제 파일에 반영한다.

7. **로그 누적.** `cs-triage/ALF_개선로그.md`에 이번 회차를 추가한다(최신이 위로, 아래 출력 형식). **현황 요약 블록의 날짜·지표·미해결 이슈도 최신으로 갱신**한다.

8. **노션 추적표 갱신.** 위 노션 페이지(`notion-fetch`로 현재 표 확인)에 이번 회차를 반영한다.
   - **이번 회차 분석 결과 표 추가**: step 4에서 만든 분석 결과를 해당 회차 섹션(`## 📋 분석 결과`)에 넣는다. 봇 발화가 있으면 per-case 표(`# / 유형 / ALF 응대 / 판정 / 문제·위반 규칙 / 개선 액션`), 없거나 수십 건이면 **유형 분포 + 반복 패턴** 요약 표.
   - **지난 회차 "다음 분석 결과" 칸 채우기**: 직전 개선점이 이번 상담에서 좋아졌나/그대로인가/확인됐나를 셀에 기록(✅확인 / 🟡부분 / ❌그대로). 핵심 지표(워크플로우 미종료·②-A 이관 건수) 변화도 적는다.
   - **이번 회차 개선점 추가**: 새 "개선점 / 배경 / 확인 방법 / 다음 분석 결과(🔲미확인)" 행을 개선점 추적 표에 더한다. 확인 방법은 "다음에 무엇을 보면 됐는지 알 수 있나"로 구체적으로.
   - 개인정보는 노션에도 옮기지 않는다(익명화).

9. **처리완료 이동.** 분석 끝난 상담 파일을 `cs-triage/상담내역/처리완료/`로 옮긴다(원본 보존, 다음 분석 때 중복 방지). `git mv`가 안 되면(미추적 파일) 일반 `mv`를 쓴다.

10. **마무리.** 변경 요약(분석 N건 / 규칙 수정 M건 / 로그·노션·엑셀 갱신 / 파일 이동)을 보고하고, 끝에 "GitHub에 push할까요? (`cspush`)"를 묻는다.

## 로그 출력 형식 (ALF_개선로그.md에 누적)

파일 맨 위 **현황 요약**은 매번 덮어쓰고, 그 아래 **개선 이력**에 새 회차를 최신순으로 끼워넣는다.

```markdown
### {오늘 날짜} | {N}차 점검
- **분석 대상**: {파일명/건수, 어떤 유형 위주}
- **잘 된 점**: ...
- **문제점**: (위반 규칙·오답·불필요 이관)
- **개선 액션**: → {수정한 규칙 파일}에 {무엇을} / 또는 "제안만, 미반영"
- **직전 대비**: (지난번 지적이 이번에 좋아졌나)
- **다음 점검 때 확인할 것**: ...
```

## 주의
- 비개발자다. 유형 코드·규칙 위반을 짚을 땐 "왜 그게 문제인지" 한 줄로 쉽게 설명한다.
- 상담 내역에 고객 개인정보(이름·전번·주소)가 있으면 로그에 그대로 옮기지 말고 마스킹하거나 "○○ 고객"으로 익명화한다.
- 규칙 파일 수정·로그 저장은 사용자 확인 후. 파일 삭제는 하지 않는다(이동만).
- 상담 건수가 많으면(수십 건+) 유형별로 묶어 표본·패턴 위주로 정리하고, 무엇을 표본으로 골랐는지 밝힌다.
