# 자격증 배송 주소 확인 스킬

배송 전에 자격증관리 시트(예: `[10월]자격증관리(월 일 결제자부터)`)에서 **배송일자가 비어 있고 주소 확인도 비어 있는 행**만 골라 판정하고, 문제 있는 칸에만 값을 넣는다. 확인 단계 없이 판정 → 입력까지 한 번에 한다(은주 결정, 2026-10-06).

- 시트는 달마다 새로 만든다. 링크를 기억해 쓰지 말 것. 은주가 링크를 주면 그 시트, 안 주면 0단계로 찾는다. 시트 탭은 `제작리스트`(gid=0).
- 열은 위치가 아니라 **머리글 이름**으로 찾는다: `배송일자`, `주소`, `주소 확인`. (2026-10 기준 A·K·U열)
- 넣는 값은 `불일치`, `동호수` 두 가지뿐이다. 문제없는 행은 빈칸으로 둔다(`일치`라고 쓰지 않음).

## 판정 기준
주소 칸은 `쉼표 앞, 쉼표 뒤` 형식이다. 쉼표 앞은 주소 검색으로 고른 주소, 쉼표 뒤는 고객이 직접 쓴 상세주소다.
- **불일치**: 쉼표 뒤에 주소(도로명이나 지번)가 적혀 있는데, 쉼표 앞 주소와 다른 곳을 가리킨다.
- **동호수**: 쉼표 앞 주소가 아파트(카카오맵 장소 분류 "아파트")인데 동·호 번호가 없다. 단, 관리사무소·경비실·택배함 같은 받을 곳을 적었으면 넣지 않는다.
- **확인필요**(시트에 안 넣음): 카카오 조회 실패, 또는 쉼표 앞 도로명과 쉼표 뒤 지번이 **같은 읍·면·동** 안에서 다른 곳으로 나올 때.
- 고객은 쉼표 뒤에 **같은 주소의 지번**을 적거나 **같은 주소를 반복**하는 경우가 대부분이다. 실제 불일치는 아주 드물다(2026-10-06: 2,118행 중 3행). 불일치가 수십 개 나오면 판정 오류부터 의심할 것.

## 0. 이번 달 시트 찾기 (링크를 안 줬을 때)
```bash
python3 .claude/skills/address-check/sheet_io.py find
```
- 이름이 `[N월]`·`[YY년 N월]`로 시작하는 자격증관리 시트 중 **만든 날이 가장 늦은 것**을 고른다(은주 결정, 2026-10-07). [11월] 시트를 10/29쯤 만들면 그때부터 11월 시트를 본다 — 이름의 월과 실제 쓰는 기간이 달라서 날짜로 계산하지 않는다.
- 템플릿 `![월]자격증관리…`·`사본 - …`은 이름 규칙에서 걸러진다.
- **진행 전에 "○○ 시트(만든 날 ○/○) 맞나요?"라고 한 줄 확인받는다.** 아니면 은주에게 링크를 받는다.
- 출력의 ID를 1·3단계의 `<시트 링크>` 자리에 그대로 넣는다.

## 1. 시트에서 대상 행 읽기
크롬 없이 웹앱(`gas-address-check/`)으로 읽는다. 결과는 저장소 **밖** 작업폴더에 둔다(고객 주소, 공개 저장소).
```bash
W="${CLAUDE_JOB_DIR:-$(mktemp -d)}/tmp/address-check"
python3 .claude/skills/address-check/sheet_io.py read "<시트 링크>" "$W"   # → $W/rows.json
```
탭 이름·열 위치·대상 행 수·`주소 확인` 열 값별 개수가 나온다. 링크에 gid가 없으면 0번 탭(제작리스트)을 읽는다.

## 2. 판정
```bash
python3 -I .claude/skills/address-check/judge.py "$W/rows.json" "$W"
```
- 카카오맵(`m.map.kakao.com/actions/searchView`)을 로그인 없이 조회한다. 2천 행에 1분 안쪽이다.
- 마지막 줄들에 `행번호 / 판정 / 주소 / 근거`가 나온다. 결과는 `$W/result.json`에 저장된다.
- `확인필요`는 카카오 조회가 안 된 행이다. **시트에 넣지 말고** 결과 보고에 따로 적는다. 직접 볼 수 있으면 보고 판단해서 불일치로 넣어도 된다.

스크립트가 이미 처리하는 고객 표기 (다시 고치지 말 것):
- 같은 주소 반복 / 띄어쓰기 없이 붙여 씀(`○○면○○1길1`) / 시·도 이름 차이
- 괄호 안 지번 `(○○리 123번지)`, `3다시6`, `396ㅡ2`, `190_24`, `217.1`, `○○길 60 16`, 앞에 붙은 말 `개인주택:…`
- 쉼표 앞 괄호 안의 쉼표 `(○○동, ○○아파트)`
- 아파트 상세의 `106-405`는 번지가 아니라 동-호. `나동 104호`·`○○동 5가 204호`·`LH아파트101동`은 주소가 아님
- 행정리·행정동 번호 `○○1리`→○○리, `○○3동`→○○동. 마을 이름만 다르고 지번 번호가 같으면 같음
- 도로명 오타(한 글자 틀림)와 길·리 혼동(`○○길152 번지` = 지번 ○○리 152)
- `○○리2구`의 `2구`는 마을 구역 이름(번지 아님) · 상세에 숫자만 `102`·`301`·`1203`(십의 자리 0)은 호수 · `○○동 8-56`처럼 도로명 번호를 동 이름과 다시 적음 (2026-10-08, 실제 오판정 4건)

## 3. 시트에 입력
```bash
python3 .claude/skills/address-check/sheet_io.py write "<시트 링크>" "$W"   # result.json의 불일치·동호수만
```
- 웹앱이 넣기 직전에 칸이 아직 비어 있는지 다시 보고, 그새 값이 생긴 칸은 건너뛴다(여러 명이 같이 편집).
- **필터가 걸려 있어도 그대로 입력된다.** 필터는 건드리지 않는다.
- 출력의 입력 전·후 `주소 확인` 열 값별 개수를 비교한다. 빈칸이 넣은 칸 수만큼 줄고 불일치·동호수가 그만큼 늘어야 한다.
- `확인필요`·받을 곳 행은 넣지 않는다.

## 4. 보고
- 입력한 칸 표: `행 | 값 | 주소 | 근거`. 불일치는 두 주소의 지번·도로명과 거리(km)를 근거로 쓴다.
- `확인필요` 행이 있으면 따로 표로 적는다. "같은 읍·면·동인데 카카오 기준 다른 곳"은 카카오 오류일 때가 많다고 한 줄 덧붙인다.
- 받을 곳(관리사무소 등)만 적은 아파트 행은 "동·호 대신 받을 곳 적음 N행"으로 한 줄 적는다.
- 검증 결과를 숫자로 적는다(예: 빈칸 4,634→4,627).

## 알려진 한계
- 카카오맵 지번↔도로명 연결이 실제와 다를 수 있다. 2026-10-06에 쉼표 앞 도로명과 쉼표 뒤 지번이 카카오 기준 약 4km 떨어진 다른 곳으로 나와 불일치로 넣었는데, 은주는 같은 주소라고 했다. → 2026-10-07부터 **도로명 vs 같은 읍·면·동 지번**이 어긋나면 `확인필요`(시트에 안 넣음). 다른 읍·면·동이면 그대로 `불일치`. 은주가 같다고 하면 그 판단을 따르고 해당 칸을 지운다.
- 동·호 대신 `관리사무소`·`경비실`·`택배함` 등 받을 곳을 적은 아파트는 2026-10-07부터 동호수로 넣지 않고 보고에만 적는다(`judge.py`의 `DROP_RE`).
- 웹앱이 403이나 JSON 아닌 응답(로그인 화면)을 주면 권한 허용이 풀렸거나 권한이 늘어난 것 — 앱스크립트 편집기에서 `authorize`를 한 번 실행한다.
