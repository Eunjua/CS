# 리포트 형식

## 목차
- 페이지 틀
- 팀 공유용: 한 문장 · 추적표 · 고객이 막힌 곳 · 없앨 수 있었던 문의
- CX 내부용: 인입 요약 · 태그 신호 · 태그 팔로업 · 상시 지표 · 운영 메모
- 해석 주의

## 페이지 틀

```
📅 데이터 기간 · 이번 주 원문: 주제별 읽은 건수
# 팀 공유용 — 한 화면 분량
  0. 이번 주 한 문장
  1. 고쳤더니 줄었다 — 조치 효과 추적표
  2. 고객이 막힌 곳 (최대 3개)
  3. 이번 주 없앨 수 있었던 문의
---
<details><summary>CX 내부용 — 운영 지표</summary>
  1. 인입 요약 · 2. 태그 신호 · 3. 태그 팔로업 · 4. 상시 지표 · 5. 원문에서 본 운영 메모
</details>
```

노션 `<details>` 안의 블록은 탭으로 들여쓴다(표의 `<tr>` 줄은 들여쓰지 않아도 된다). 저장 후 다시 열어 토글 안 내용이 다 들어갔는지 본다.

## 팀 공유용

**팀원 업무 목록은 넣지 않는다** — 리포트가 흐려지고 평가처럼 읽힌다. 팀원의 일은 CS 회의록 공유사항 중 VOC와 연결된 것만 추적표에 팀 이름으로 드러난다.

### 0. 이번 주 한 문장

"고객이 이번 주에 어디서 가장 많이 막혔고, 무엇이 나아졌나". 태그 이름·증감률은 쓰지 않는다.

### 1. 고쳤더니 줄었다 — 조치 효과 추적표

열: `변화·조치 | 공유일 | 팀 | 대상 문의 추이 (최근 4주) | 판정`

- 행은 **직전 리포트에서 이어받는다**(추적표가 없는 첫 회면 새로 만든다). 새 행은 회의록에서 **누가 뭘 바꾸거나 요청하기로 한 것**(어느 칸에 적혔든)과 은주가 알려준 것에서만 추가한다. **대상 문의 태그를 하나라도 댈 수 있을 때만** 넣는다 — 못 대면(유튜브 운영 등) 뺀다.
- **공유일:** 회의록 날짜(정확한 반영일은 회의록에 없다). 은주가 알려준 건 은주가 말한 날짜.
- **대상 문의 추이:** 대상 태그 묶음의 최근 4주 값(`57 → 70 → 74 → 58`) — `trend.py`로 뽑고 묶음은 다음 주에도 그대로 쓴다.
- **판정:** 조치 이후 대상 태그 묶음의 주차별 값과 `trend.py` 판정으로 정한다.
  - ✅ 효과 있음 — 조치 후 2주 연속 전주보다 줄었고, 이번 주 판정이 `줄었다`
  - 🟡 확인 중 — 줄었지만 아직 1주이거나, 판정이 `비슷` 범위
  - ❌ 변화 없음 — 조치 후 2주가 지났는데 줄지 않음
  - 📨 요청됨(아직 반영 전) · ⬜ 확인 안 됨
  - ✅가 된 행은 다음 주에 한 번 더 보여주고 뺀다.
- **팀:** 회의록에 적힌 팀 이름 그대로(성장엔진, 제품팀, CX). 요청 건은 `CX → 제품`. 개인 이름은 쓰지 않는다.
- 같은 주에 변화가 여러 개면 어느 쪽 효과인지 태그 건수로는 못 가른다. 원문으로 확인한 것만 "때문에"라고 쓴다.

### 2. 고객이 막힌 곳 (최대 3개)

**원문을 분류한 주제만** 쓴다. 섹션 맨 위에 한 번:

```markdown
> 📊 **숫자 읽는 법** — 최근 4주는 08/17주 → 08/24주 → 08/31주 → **09/07주(이번 주)** 순서입니다. 이번 주가 앞 3주 평균보다 **20% 이상 그리고 5건 이상** 차이 날 때만 "늘었다/줄었다", 아니면 "비슷"으로 적습니다. 태그 없는 문의(약 18%)는 빠져 있습니다.
```

이어서 **원문 전체 분류표** — 원문을 받은 주제마다 하나(`tally.py` 출력으로):

```markdown
### 원문 전체 분류 — 고객이 왜 문의했나
> 주제별 전체 건수, 한 상담 = 주된 이유 하나, 여러 주제에 겹친 상담 수
**환불·수강취소 — 84건**
| 원인 | 건수 (%) | 고객이 한 말 | 처리 결과 | 시점 |   ← 건수 많은 순, 합계 = 원문 건수
**자격증 신뢰 — 대화 중 한 번이라도 나온 걱정**
| 걱정 | 상담 수 (%) |   ← 이유가 섞이는 주제일 때만
```

- 원인 이름은 고객 입장의 말로(`A2` 같은 코드는 쓰지 않는다). 처리 결과는 상위 2~4개만 쓰고 나머지는 `기타 n`.
- 1~2건짜리 원인은 비슷한 것끼리 합친다(예: 앱 오류·배송 문제).
- 막힌 곳 덩어리는 이 표의 어느 줄에서 나왔는지 규모 줄에서 밝힌다.

덩어리 형식:

```markdown
### 1. [결제] 결제하고 나서야 "이걸로 무슨 일을 할 수 있는지" 알게 되고, 기대와 다르면 환불합니다
**최근 4주 문의 (결제 후 환불):** 40 → 52 → 32 → **42건** · 전체 문의의 3.5% · 앞 3주 평균 41건 대비 **비슷 (+2%)**   ← trend.py 출력 그대로
> 📎 태그 묶음: 아카데미_환불/자격증, 아카데미_환불/거부   ← trend.py 출력 그대로
**고객이 한 말:** *"…"* · *"…"*   ← 이름·숫자 빼고
**규모:** 결제 후에 온 환불·취소 문의 44건 중 22건이 할 수 있는 일이 기대와 달라서(11) · 민간인 줄 몰라서(7) · 이미 자격이 있어서(4) — 원문 84건 전체 분류 기준
**누가 뭘 하면 사라지나:** 성장엔진·제품 — 결제 직전 세 줄 안내 (문구 수정)
```

- **여정 단계는 고정 목록에서만:** `탐색 → 수강 신청 → 수강 → 시험 → 결제 → 발급·배송 → 활용`.
- **제목은 고객 입장의 문장.** 태그 표기(`환불/자격증 +44%`)는 제목에 쓰지 않는다.
- **태그 묶음은 덩어리별로 정한다.** 원문 요청 때의 주제 전체 묶음이 아니라 그 덩어리 결론에 해당하는 태그만 넣는다. 직전 리포트의 📎 줄에 같은 덩어리가 있으면 그 묶음을 그대로 쓴다. 초안 승인 때 은주에게 묶음을 같이 보여준다.
- **규모는 분류한 원문 기준 "최소 ○건"으로 쓴다.** 태그 없는 상담(약 18%)은 export에 안 잡힌다. 어쩔 수 없이 일부만 읽은 주는 "표본 ○건 기준"이라고 밝히고 전체로 부풀리지 않는다.
- **원인을 단정하지 않는다.** 원문으로 확인한 것만 "때문에", 나머지는 "같은 줄기로 보인다" 수준으로 쓴다.
- **해법에 난이도를 붙인다:** 문구 수정 / 설정 / 매크로 / 정책 / 개발.
- 4주 판정 뒤에 한 줄 해석을 붙여도 된다(예: "한 주씩 번갈아 오르내려 다음 주에 한 번 더 봅니다").

### 3. 이번 주 없앨 수 있었던 문의

"읽은 원문 ○건 중 ○건은 문구·설정 하나로 사라질 문의였습니다 — 원인별 건수". 분류표의 원인 줄로 센다. 여러 주제에 겹친 상담·여러 원인에 걸린 상담은 한 번만 센다.

## CX 내부용

### 1. 인입 요약

열 `지표 | 이번 주 | 전주 | 증감`. 행: 총 인입 · 채팅 · 전화 · AI 완결 · 상담원 응대 · 부재중(`부재중률` 전체 대비 / `전화대비부재중률`) · 상담 만족도(응답수) · 친절도 · "해결됐어요" 비율. 표 아래 한 줄 해석(눈에 띄는 대비).

AI 해결률은 두 기준을 나란히 쓴다: 전체 중 AI가 끝낸 비율(`AI완결률` — 지금은 측정 불가) · AI가 붙은 건 중 완결률과 이탈률(ALF 개선로그 최신 회차 — 몇 차·측정 기간을 같이, 리포트 주차와 다를 수 있다).

### 2. 🔍 태그 신호

`analyze.py`의 `급증`·`급감`·`신규`·`급부상`·`기타계열`·`연속추세`·`태그추세`에서 최대 3개(고르는 순서는 `selection-rules.md`). 나머지는 `<details>` "그 외 변동" 표.

```markdown
### 1. 콜백/부재중 +80% — 30건 → 54건
(맥락 한두 줄. 4주 흐름을 보면 평소 수준인지도 적는다.)
> 📎 채널톡에서 [태그: 콜백/부재중] + [기간: 08/03~08/09] 필터 → 54건
> **원인:** 확인 필요 (원문을 읽었으면 "팀 공유용 N번 참고", 회의록 태그 결정이면 그 내용)
```

연속추세는 3주 값을 같이 보여주고, **응답수가 함께 줄었으면 반드시 밝힌다**(응답수는 `analyze.py`의 이번 주·전주 값까지만 있다).

### 3. ✅ 태그 팔로업

직전 리포트의 "태그 신호"(옛 리포트는 "이번 주 볼 것") 항목을 행으로. 열 `지난주 항목 | 이번 주 | 결과`, 결과는 ✅ 해소 / 🟡 진행 중 / ❌ 그대로 / ⬜ 확인 안 됨. 첫 회면 생략.

### 4. 상시 지표

- **태그없음 비율** — 높을수록 태그 분석 전체가 흔들린다고 한 줄.
- **만족도 응답률** — 만족도를 얼마나 믿을 수 있는지.
- **대기 체감 설문**(`설문`의 `대기적절`) — 만족도가 올라도 "😞 너무 오래 기다렸어요"만 역행할 수 있어 따로 본다. 대시보드 대기시간초와는 대조하지 않는다(빈칸 45%·0초 32%).

### 5. 원문에서 본 운영 메모

매크로 문구가 낡았다, 태그가 섞였다 같은 운영 이슈. **특정 응대 문제(고객 탓 문구, 개인정보를 채팅으로 요청 등)는 리포트에 넣지 않고 은주에게만 알린다** — 팀 전체가 보는 페이지다.

## 해석 주의

- **전주 대비만 보고 늘었다고 쓰지 않는다.** 한 주 낮았던 뒤의 회복이 +40%대로 보인다. 팀 공유용은 `trend.py` 판정, CX 내부용 태그 신호에도 4주 흐름을 한 줄 붙인다.
- 태그 체계가 바뀌면 급감에 −100%가 뜬다 — 태그가 사라진 건지 문의가 사라진 건지 구분한다(회의록 태그 결정부터 본다).
- 만족도 응답수가 100건 아래면 평균 해석에 주의 문구. 설문은 늦게 채워져 지난 주 값이 바뀐다 — 최신 조회 기준이라고 밝힌다.
- **부재중률은 분모를 둘 다 쓴다.** 대시보드 값은 전체 인입 대비인데 부재중은 사실상 전화에서만 생겨, 전화 대비로 보면 약 2배다.
