## 대시보드 집계 (`analyze.py`)

대시보드 v2 웹앱(`gas-v2/WebApp.gs`)이 집계 시트를 JSON으로 내보내고, `analyze.py`가 계산한다.

출력: `인입요약` · `급증` · `급감` · `신규` · `급부상` · `기타계열` · `연속추세` · `태그추세` · `설문` · `상시지표`.

**집계에 없는 것** — 요청받으면 "지금 데이터로는 안 나온다"고 말한다: 점수 분포(1~5점별), 태그별 만족도, 고객 코멘트 원문, 재문의율, 당일응대율.

**`AI완결`은 09/07~09/13 주차부터 쓸 수 없다.** 9월부터 `AI/상담완료`·`AI/상담원이관` 태그를 안 붙이기로 해서(의도된 운영) 태그 기반 집계가 끊겼다. `상담원응대`도 그만큼 부풀려진다. 대시보드 기준이 "상담원 배정 여부"로 바뀌기 전까지 표에 `측정 불가`로 쓰고, AI 해결률은 `cs-triage/ALF_개선로그/최신_*.md` 최신 회차 값만 쓴다(몇 차·언제 측정인지 같이).

**채널별 만족도**(은주가 요청할 때만)는 상담원별 값으로 근사한다 — 상담원마다 담당 채널이 정해져 있다. 누가 어느 채널인지는 개인 메모 `cs-agent-channel-mapping`에 있다(공개 저장소라 여기엔 이름을 안 적는다). `agent` 데이터를 채널로 갈라 응답수 가중평균하고, 두 채널을 겸하는 사람은 뺀다. **상담원별 표를 개인 성과 비교로 쓰지 않는다** — 차이는 대개 채널 차이다. 노션 리포트엔 이름을 써도 되지만(사내 문서) 이 저장소 파일엔 쓰지 않는다.

## 주제별 4주 추이 (`trend.py`)

같은 웹앱의 주차별 태그 건수로 계산한다. 태그 묶음은 **고객이 막힌 곳 덩어리별로** 그 결론에 해당하는 태그만 넣는다(원문 요청 때의 핵심+선택 태그에서 고른다). 출력의 숫자 줄과 `📎 태그 묶음` 줄을 팀 공유용에 그대로 붙인다. 데이터에 없는 태그 이름이 있으면 경고가 나온다 — 오타인지 확인한다.

## CS 회의록 (노션)

- **위치:** 「CS 회의」 페이지(`2bd72773c36380409d3cd9b1cde9643a`)의 자식 페이지. 제목이 `26년 9월 8일` 형식인 것만 본다(주제 회의 페이지도 섞여 있다).
- **주차 맞추기:** 월요일 팀 전체 회의 내용을 화요일 CS 회의에서 전달한다. 리포트 주차(월~일)의 화요일 회의록이 그 주 회의록이다(09/07~09/13 → `26년 9월 8일`). 리포트는 월요일에 만들어 다음 날 회의록의 "VOC 인입 추이 공유" 칸에서 쓴다.
- 회의록이 없는 주(휴무 등)는 건너뛰고 은주에게 알리기만 한다.

| 회의록 칸 | 리포트에서 쓰는 곳 |
|---|---|
| 공유사항 (어느 팀이 뭘 하나 — CS 영향 있는 것만 적혀 있다) | 팀 공유용 추적표의 행 |
| 요청사항 (백로그 요청 등) | 추적표에 `📨 요청됨`으로 |
| VOC 특이사항 (상담원 현장 감각) | 원문 주제 후보 |
| 논의사항·특이사항 속 **태그 결정** | CX 내부용에서 태그 증감 설명 — 은주에게 따로 묻지 않는다 |

칸 이름보다 **내용으로** 나눈다 — 요청이 논의사항이나 특이사항 칸에 적혀 있기도 하다. "누가 뭘 바꾸거나 요청하기로 했다" → 추적표 후보, "이런 문의가 많다" → 주제 후보, "태그를 이렇게 붙이자" → 태그 증감 설명.

**옮기지 않는 것:** 회의록의 채널톡 상담 링크(URL에 고객 전화번호가 들어 있다), 상담원 이름. 저장소 파일에는 절대 쓰지 않고 노션 리포트에도 링크는 옮기지 않는다.

회의록에 안 올라오는 조치도 있다 — 그래서 원문 요청 메시지에서 "회의록에 없는데 지난주 반영된 조치가 있나요?"를 묻는다.

## 원문 export (`sample_chats.py`)

- **위치:** `voc-원문/MMDD/`(리포트 만드는 날). `cs-triage/`는 ALF 분석 전용이라 섞지 않는다. 은주가 폴더 없이 `voc-원문/` 바로 아래에 올리기도 한다 — 그 경우 그 폴더를 넣는다.
- `voc-원문/`은 `.gitignore`로 통째로 막혀 있다. 이 폴더 내용을 다른 곳(특히 저장소 안)으로 옮기지 않는다. 파일은 처리 후에도 그대로 둔다.
- **구조:** `UserChat` 시트(상담 1건 = 1행, `tags`·`mediumType`·`managedAt`) + `Message data` 시트(`chatId`·`personType`(user/manager/bot)·`plainText`·`isPrivate`). `isPrivate=True`는 내부 메모라 뺀다.
- 채널톡은 한 태그로 뽑아도 **채널별로 파일을 나눠 준다**(케어파트너 앱·전화 / 케어아카데미 앱·봇). 파일 이름이 `환불수강취소.xlsx`·`환불수강취소2.xlsx`처럼 온다.
- 먼저 대시보드 건수와 export 건수를 태그별로 맞춰 본다. **핵심 태그가 5건 넘게 그리고 20% 넘게** 차이 나면 기간·태그 선택을 은주에게 확인한다. 선택 태그는 안 뽑았을 수 있어 차이가 커도 괜찮다.
- 원문이 안 오면 그 주제는 원문 분석을 건너뛰고 CX 내부용에만 `확인 필요`로 남긴다.

## 원문 분류를 하위 에이전트에게 맡기기

원문 30건은 메인 대화를 크게 차지한다. `sample_chats.py` 결과 파일을 하위 에이전트(Agent 도구)에게 넘기고 결과만 받는다. 프롬프트 틀:

```
<raw_주제.txt 경로>의 상담 원문을 전부 읽고 분류해 주세요. 파일을 수정하거나 다른 곳에 옮기지 마세요.
주제: <주제 이름> / 이번 주 궁금한 점: <후보로 고른 이유>
돌려줄 것:
1. 분류표 — "고객이 원한 것" 기준 카테고리별 건수(합계 = 읽은 건수)와 chat 8자리 목록
2. 카테고리마다 막힌 지점 한 줄, 처리 결과(해결/안내 후 이탈/미해결) 건수
3. 인용하기 좋은 고객 발화 3~5개 — 이름·한글로 읽은 숫자·주소는 빼고, chat 8자리 병기
4. 리포트엔 넣기 곤란하지만 CX 리더가 알아야 할 응대 이슈(개인정보 요청, 고객 탓 문구 등) — chat 8자리만, 상담원 이름 없이
건수는 읽은 건 기준으로만 세고, 추정은 "추정"이라고 표시해 주세요.
```

받은 분류는 몇 건을 무작위로 원문과 대조해 본다(분류가 맞는지, 인용이 실제 발화인지).
