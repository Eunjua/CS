# 자격증 신뢰 — 매주 고정 섹션 (진행순서 4~6번에서 읽는다)

2026-10-12 은주 결정: **신뢰 관련은 매주 리포트한다.** 주제 후보로 고르지 않는다. 리포트의 독자는 **각 팀** — 팀이 "우리가 고치면 몇 건이 사라지나"를 보고 정비 우선순위를 정하게 한다(4분기 CX 방향, 10/6 CS 회의 Narrative).

## 기준은 `trust.json` 한 곳에 — 매주 같은 기준

| 칸 | 뜻 | 바꿔도 되나 |
|---|---|---|
| `tags` | 신뢰 원문을 거르는 태그 5개 | **바꾸면 주차 비교가 끊긴다.** 태그 체계가 바뀌었을 때만 은주와 정하고 리포트에 "몇 주차부터 묶음 변경"을 적는다 |
| `categories` · `rules` · `boundaries` | 원인 11개(code·desc·고객 말 예시) · 판단 순서 · 경계 규칙 | 같은 이유. 바꾸면 `version`을 올린다(v1 = 10/05주~). `기타`가 2주 연속 같은 이야기로 5건 넘으면 새 원인 추가를 은주에게 제안 |
| `gold` | 기준 표본 — 은주가 정답을 확정한 상담 번호와 원인. `확인 필요`는 대조에서 뺀다 | 은주 확정으로만 |
| `board` | 지표판에 올릴 이유(true) / CX 내부용으로 보낼 이유(false) | 은주 결정으로만 |
| `fix` | 원인별 고칠 것 | 버전 그대로 고쳐도 된다. **담당 팀(`team`)은 10/12 은주 결정으로 일단 뺐다** — 정해지면 원인마다 `team`을 다시 넣으면 지표판·합계에 자동으로 나온다 |

분류 프롬프트의 기준 부분은 **`python3 trust_prompt.py > <저장소 밖>/기준표.txt`로 뽑아** 에이전트에게 준다 — 손으로 옮겨 적지 않는다.

**환불은 원인이 아니다(v1, 은주 결정).** 분류 줄에 `refund: true/false`를 따로 두고, 원인은 환불한 이유로 정한다. 지표판에는 "인정 12건 (그중 환불 3건)"처럼 원인마다 환불 건수를 붙인다. 결제 후 환불은 신뢰 문제의 가장 비싼 결과라 합계도 따로 낸다.

## 매주 돌리는 법

```bash
S=.claude/skills/voc
python3 $S/sample_chats.py 채널톡 --by-tag "신뢰=<trust.json tags 쉼표로>" --chunk 40 --out <저장소 밖 폴더>
# 묶음별 하위 에이전트 분류(data.md 프롬프트) → cls_신뢰N.jsonl
# 기준 표본 15건도 같이 분류 — 처리완료 원문에서 상담 번호로 뽑는다(이번 주 신뢰 원문에 들어 있으면 따로 안 뽑아도 된다)
python3 $S/sample_chats.py 채널톡/처리완료 --chats "기준=<trust.json gold items 상담 번호>" --out <같은 폴더>
python3 $S/tally.py <같은 폴더> 신뢰 [기준] --total <총건수> --chat <채팅> --phone <전화> --week <주차> --save
```

- `--save`는 **빠짐·겹침 0 + 기준 표본 일치율 80% 이상**일 때만 `trust_history.json`에 그 주를 쓴다(같은 주는 덮어씀). 못 미치면 틀린 표본을 보고 기준표(경계·예시)를 고치거나 그 묶음을 다시 분류한다 — 기준을 고쳤으면 `version`을 올린다.
- **전화/채팅:** `--chat`·`--phone`을 주면 채널별 신뢰 비중과 원인별 채널 나눔이 나오고 기록에도 남는다. 연휴처럼 전화가 크게 준 주에 비중이 움직이면 이 줄부터 본다.
- `trust_history.json`에는 주차별 건수만 있다(개인정보 없음). 첫 기록은 10/05~10/11.

## 숫자 두 종류 — 섞지 않는다

| | 어디서 | 무엇을 말하나 | 리포트 자리 |
|---|---|---|---|
| **원문 이유 비중** | `tally.py` 신뢰 지표판 | "전체 문의 중 몇 %가 이 이유로 왔나" — 원문을 읽고 센 상담 수 ÷ 그 주 전체 문의 | 신뢰 지표판 · 원인별 카드 |
| **태그 4주 추이** | `trend.py` | "이 태그가 붙은 문의가 늘었나" — 대시보드 태그 건수(한 상담에 태그 2개면 두 번 셈) | 추적표 · CX 내부용 |

- 10/05주: 원문 146건 = 전체의 18.2% / 태그 합 157건 = 19.6%. **같은 문장에 두 숫자를 나란히 쓰지 않는다.** 지표판의 "신뢰 문의 비중"은 원문 기준이다.
- 비율 기본은 **전체 문의 중 %**(연휴로 전체가 줄어도 비교된다). 건수는 괄호로.
- 4주 판정은 `tally.py`가 낸다 — 기록이 4주가 안 되면 "기록 N주 — 4주부터 판정"을 그대로 쓰고, 전주와 비교해 늘었다·줄었다를 쓰지 않는다.

## 원인별 카드에 들어갈 것 (담당 팀을 정하기 전까지)

지표판 순서(건수 많은 순)대로 상위 원인마다:
- **이번 주 ○건 (전체 문의의 ○%) · 그중 환불 ○건**
- **고칠 것** — `trust.json` `fix` (난이도: 문구 수정 / 설정 / 정책 / 개발)
- **고객 한 마디** — 그 이유 상담의 quote 하나(이름·숫자 없이)
- **이번 주 새로 보인 것** — 원문에서 확인한 것만. 없으면 쓰지 않는다

`board=false` 원인(결제관련·기타)은 카드에 넣지 않고 CX 내부용 "원문에서 본 운영 메모"에 건수만 둔다.
