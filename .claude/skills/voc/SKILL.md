# VOC 주간 리포트

팀 전체가 보는 노션 페이지 하나에 **팀 공유용**(신뢰 지표판·원인별 카드·조치 효과)과 **CX 내부용**(태그 증감·운영 지표)을 위아래로 둔다.

> **v2 (2026-10-12 은주 결정)** — 독자는 각 팀(정비 우선순위를 정함). **자격증 신뢰는 매주 고정**, 그 밖의 주제는 튄 신호가 있을 때만. 비율은 **전체 문의 중 %**. → [reference/trust.md](reference/trust.md)

## 은주가 하는 일 — 그 밖은 스킬이 한다

1. **그 밖의 신호 고르기** — 튄 신호가 있을 때만, 제안된 것 중 고르거나 건너뜀 (4단계). 신뢰는 고르지 않는다(매주 고정)
2. ~~원문 올리기~~ — 없어짐(2026-10-07). 월요일 `채널톡/`에 넣은 전체 export에서 태그로 거른다
3. **초안 승인** — 팀 공유용 핵심 확인 (7단계)
4. **공유** — 「자격증 신뢰 추이」 대시보드는 처음 한 번 은주가 공유 메뉴에서 팀에 공유한다(이후 매주 갱신은 스킬이 한다)

그 사이는 스킬이 진행한다. 막히면 멈추고 묻는다.

## 꼭 지킬 것

- **숫자는 스크립트 출력에서만.** 손으로 채우지 않는다. 스크립트 값끼리의 증감(뺄셈)만 직접 해도 되고, 새 비율·합계가 필요하면 스크립트에 추가한다. 웹앱이 재시도 뒤에도 실패하면 알리고 멈춘다.
- **팀에 전하는 건 "우리 팀이 무엇을 고치면 전체 문의의 몇 %가 사라지나"다.** 태그 증감은 무엇을 읽을지 고르는 신호로만 쓴다.
- **원문 이유 비중(`tally.py`)과 태그 4주 추이(`trend.py`)를 섞지 않는다.** 둘은 분모가 다르다(→ trust.md 「숫자 두 종류」).
- **"왜"는 지어내지 않는다.** 원문에서 읽거나 은주에게 묻고, 없으면 `확인 필요`.
- **늘었다·줄었다는 최근 4주로 판정한다**(`trend.py`). 전주 대비만으로 쓰지 않는다.
- **개인정보:** 고객 이름·전화번호·주소·계좌, 채널톡 상담 링크(URL에 전화번호), 상담원 이름을 이 저장소 파일에 쓰지 않는다. 노션 인용은 마스킹. `채널톡/`·`voc-원문/` 내용은 저장소로 옮기지 않는다.
- **은주는 비개발자다.** 지표마다 "왜 문제인지" 한 줄로 쉽게.

## 스크립트

```bash
S=.claude/skills/voc
python3 $S/analyze.py [09/07~09/13]                                   # 집계·태그 신호 JSON (인자 없으면 최신 주차)
python3 $S/trend.py 09/07~09/13 "주제 이름=태그1,태그2" ...             # 주제별 최근 4주 줄
python3 $S/sample_chats.py 채널톡 --by-tag "A=태그1,태그2" ... --chunk 40 --out <저장소 밖 임시 폴더>   # 원문 전체·마스킹·근거 링크·묶음
python3 $S/tally.py <같은 폴더> A B [--reassign chat8=원인 ...]         # 분류 결과 검증·원인별 집계
python3 $S/trust_prompt.py > <저장소 밖>/기준표.txt                     # 신뢰 분류 기준표(trust.json에서)
python3 $S/trust_links.py <같은 폴더> > <저장소 밖>/notion_links.md     # 지표판 아래 원인별 상담 링크 토글
python3 $S/trust_dashboard.py <저장소 밖 폴더>                       # 추이 대시보드용 파일 2개(올리는 법은 trust.md)
python3 $S/sample_chats.py 채널톡/처리완료 --chats "기준=<표본 번호>" --out <같은 폴더>   # 기준 표본 다시 뽑기
python3 $S/tally.py <같은 폴더> 신뢰 기준 --total <총건수> --chat <채팅> --phone <전화> --week <주차> --save   # 지표판·환불·채널·표본 대조·기록
```

스크립트를 고치면 `trend.py --selftest`, `sample_chats.py --selftest`, `tally.py --selftest`, `trust_prompt.py --selftest`, `trust_links.py --selftest`, `trust_dashboard.py --selftest`를 돌린다.

## 진행 순서

1. **주차 확인.** 인자가 없으면 최신 주차. 노션 「자동 리포트」(`34972773c36380e18445e03264de9caa`)에 이미 그 주차가 있으면 알리고 덮어쓸지 묻고, **답을 받은 뒤** 진행한다.
2. **`analyze.py` 실행.**
3. **이어받기.** 직전 주차 리포트에서 추적표 행과 CX 내부용 "태그 신호"를 가져온다. **CS 회의록은 읽지 않는다**(2026-10-20 은주 결정 — 지금 회의록은 팀 전체 회의). 추적표 새 행은 은주가 전달한 조치에서만 만든다.
4. **신뢰 원문 뽑기 + 그 밖의 신호.**
   - **신뢰는 묻지 않고 바로** — `sample_chats.py 채널톡 --by-tag "신뢰=<trust.json tags>" --chunk 40 --out <저장소 밖>`. 대시보드 태그 합과 원문 건수 차이를 한 줄로 알린다(한 상담에 태그 2개면 대시보드가 두 번 센다).
   - **그 밖의 신호**는 `selection-rules.md` 「그 밖의 신호」에 해당하는 게 있을 때만 1개를 제안한다(핵심 태그 2~3개·건수·4주 판정·왜 지금인지). 없으면 "그 밖의 신호 없음"이라고만 알린다.
   - 조치 목록은 묻지 않는다(2026-10-26 은주 결정 — 생기면 은주가 먼저 알려 준다). 받은 조치가 없으면 추적표는 빈 표 한 줄만 둔다.
5. **원문 전체 분류.** 표본이 아니라 **올라온 원문 전부**를 분류한다(은주 지시). 신뢰는 `trust.json` 기준표 그대로. `sample_chats.py --chunk 40`으로 묶음을 만들고, 묶음마다 하위 에이전트에게 **같은 원인 기준표**로 맡겨 상담 한 건당 한 줄(JSONL)을 받는다(프롬프트 틀은 `data.md`). 건수는 `tally.py`로 센다 — 에이전트가 센 숫자를 쓰지 않는다. 빠짐·겹침이 나면 그 묶음만 다시 맡기되 **3회까지**, 그래도 안 맞으면 멈추고 은주에게 묻는다. 직접 5~10건 읽어 대조하고 **10건 중 7건 미만**이면 기준표를 고쳐 그 주제만 다시 분류한다. **한 묶음이라도 어긋나 있으면 그 주제 분류표를 쓰지 않는다**(자세한 규칙은 `data.md`). 원문이 없는 주제는 건너뛴다. 신뢰는 `trust_prompt.py`로 뽑은 기준표를 주고, 기준 표본 15건(`sample_chats.py 채널톡/처리완료 --chats`)도 같이 분류한 뒤 `tally.py … 신뢰 기준 --total --chat --phone --week --save`로 지표판을 내고 기록한다 — 표본 일치율 80% 미만이면 기록되지 않는다(→ trust.md).
6. **4주 숫자.** 신뢰 이유별 4주는 `tally.py`가 낸다. 추적표 행과 그 밖의 신호는 **덩어리마다** 그 결론에 해당하는 태그 묶음을 정해 `trend.py`에 넣는다(주제 전체 묶음 아님). 출력의 `📎 태그 묶음` 줄도 리포트에 붙인다 — 다음 주에 같은 묶음으로 이어 보고, 추적표 판정도 같은 줄로 한다.
7. **초안.** `report-format.md`대로 쓰고 은주에게 핵심을 보여 승인받는다. 리포트에 넣기 곤란한 응대 이슈는 은주에게만 따로 알린다.
8. **저장 전 점검.** 아래를 하나씩 확인하고, 걸리면 고친 뒤 저장한다. 전부 실제로 났던 사고다.
   - 숫자가 전부 스크립트 출력에서 왔나 — 손으로 한 건 스크립트 값끼리의 뺄셈뿐인가. 지표판·원인별 카드의 %가 `tally.py` 신뢰 지표판 출력과 같은가
   - 원문 이유 비중과 태그 4주 추이가 한 표·한 문장에 섞이지 않았나
   - 덩어리의 `📎 태그 묶음`과 추적표 행의 묶음이 같은가, 판정이 서로 모순되지 않나(4주 판정 `비슷`인데 ✅ 같은 것)
   - "늘었다·줄었다"가 전부 `trend.py` 4주 판정에서 왔나 — 전주 대비로 쓴 곳은 없나
   - 개인정보 — 고객 이름·전화번호·계좌·주소, 상담원 이름이 **인용문까지 포함해** 없나. 상담 링크는 지표판 아래 「원인별 상담 링크」 토글 안에만, `trust_links.py`가 만든 `desk.channel.io/…/user-chats/{상담 ID}` 형식만 있나(닉네임 들어간 링크 금지)
   - 규모 숫자가 `tally.py` 출력과 맞나, 분류표 합계 = 원문 건수인가
   - 팀 공유용 0~3번이 다 있나(4번은 그 밖의 신호가 있을 때만), 원문을 안 읽은 주제가 팀 공유용에 올라가 있지 않나
   - 응대 이슈·팀원 업무 목록이 리포트 본문에 섞이지 않았나
9. **노션 저장.** 제목 `26년 9월 7일~13일 VOC 리포트`(달을 넘으면 `26년 8월 31일~9월 6일 VOC 리포트`, 연도는 실행 시점). 저장 후 다시 열어 두 파트가 다 들어갔는지 확인하고 URL과 근거 링크 파일 위치를 알린다.
10. **신뢰 업데이트 — 매주, 노션 저장 뒤.** 하나라도 못 하면 마무리에 무엇을 왜 못 했는지 쓴다.
   - **리포트 신뢰 세 가지가 들어갔나** — 신뢰 지표판(전체 문의 중 %·그중 환불·채팅/전화) · 그 아래 「📎 원인별 상담 링크」 토글(`trust_links.py` 출력 그대로) · 원인별 카드(상위 3~5개, `trust.json` `fix`). 숫자는 이번 주 `tally.py` 신뢰 지표판 출력과 같아야 한다.
   - **추이 대시보드 갱신** — `trust_dashboard.py` → 두 파일을 대시보드 자산으로 올리고 `datasets/weekly`·`datasets/causes`의 `source.url`·`updated`만 바꾼다(→ trust.md 「추이 대시보드」). 갱신 뒤 두 데이터셋을 다시 읽어 새 url이 들어갔는지 보고, **화면을 한 번 열어** 이번 주 숫자와 "지난주 대비"가 나오는지 확인한다. 평소 주에는 화면을 손대지 않는다.
   - **기준 표본이 80% 미만이었던 주** — 기록(`--save`)·대시보드 갱신을 하지 않고, 리포트 지표판 위에 "이번 주는 분류 확인 중"을 쓰고 틀린 표본을 은주에게 보여준다.
   - **기준 버전을 바꾼 주** — 노션 「신뢰 관련 원인 분석 기준」 본문과 「변경 이력」을 같은 날 고친다(문구는 먼저 보여주고 "써줘" 후). 리포트 지표판 위에 "○주부터 기준 v○ — 이전 주와 직접 비교하지 않음". **추이 대시보드 화면도 같은 날 고친다**(기준 안내 한 줄·판정 시작 주·지난주 대비 계산·데이터 설명 — trust.md 「추이 대시보드」).
   - **"기타" 감시** — 기타 안에 같은 이야기가 2주 연속 5건을 넘으면 새 원인 후보로 은주에게 제안한다(정해지기 전엔 `trust.json`을 바꾸지 않는다).
11. **마무리.** 변경 요약을 보고하고 "GitHub에 올릴까요?"를 묻는다(CLAUDE.md Git 규칙). 요약에 신뢰 한 줄을 넣는다 — 신뢰 문의 비중(채팅/전화) · 1위 원인과 비중 · 결제 후 환불 합계 · 기준 표본 일치 · 대시보드 갱신 여부와 링크.
