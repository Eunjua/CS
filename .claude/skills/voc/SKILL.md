# VOC 주간 리포트

팀 전체가 보는 노션 페이지 하나에 **팀 공유용**(고객이 막힌 곳·조치 효과)과 **CX 내부용**(태그 증감·운영 지표)을 위아래로 둔다.

## 꼭 지킬 것

- **숫자는 스크립트 출력에서만.** 손으로 채우지 않는다. 스크립트 값끼리의 증감(뺄셈)만 직접 해도 되고, 새 비율·합계가 필요하면 스크립트에 추가한다. 웹앱이 재시도 뒤에도 실패하면 알리고 멈춘다.
- **팀에 전하는 건 "고객이 어디서 막혔고, 누가 뭘 하면 사라지나"다.** 태그 증감은 무엇을 읽을지 고르는 신호로만 쓴다.
- **"왜"는 지어내지 않는다.** 원문에서 읽거나 은주에게 묻고, 없으면 `확인 필요`.
- **늘었다·줄었다는 최근 4주로 판정한다**(`trend.py`). 전주 대비만으로 쓰지 않는다.
- **개인정보:** 고객 이름·전화번호·주소·계좌, 채널톡 상담 링크(URL에 전화번호), 상담원 이름을 이 저장소 파일에 쓰지 않는다. 노션 인용은 마스킹. `voc-원문/` 내용은 저장소로 옮기지 않는다.
- **은주는 비개발자다.** 지표마다 "왜 문제인지" 한 줄로 쉽게.

## 스크립트

```bash
S=.claude/skills/voc
python3 $S/analyze.py [09/07~09/13]                                   # 집계·태그 신호 JSON (인자 없으면 최신 주차)
python3 $S/trend.py 09/07~09/13 "주제 이름=태그1,태그2" ...             # 주제별 최근 4주 줄
python3 $S/sample_chats.py voc-원문/0914 "A=파일앞부분" ... --chunk 40 --out <저장소 밖 임시 폴더>   # 원문 전체·마스킹·근거 링크·묶음
python3 $S/tally.py <같은 폴더> A B [--reassign chat8=원인 ...]         # 분류 결과 검증·원인별 집계
```

스크립트를 고치면 `trend.py --selftest`, `sample_chats.py --selftest`, `tally.py --selftest`를 돌린다.

## 진행 순서

1. **주차 확인.** 인자가 없으면 최신 주차. 노션 「자동 리포트」(`34972773c36380e18445e03264de9caa`)에 이미 그 주차가 있으면 알리고 덮어쓸지 묻고, **답을 받은 뒤** 진행한다.
2. **`analyze.py` 실행.**
3. **이어받기.** 직전 주차 리포트에서 추적표 행과 CX 내부용 "태그 신호"를 가져온다. 이어서 CS 회의록 두 개(리포트 주차의 화요일 회의록 + 그 전 주)를 읽고 내용별로 나눠 담는다 → `data.md` "CS 회의록". 직전 리포트에 추적표가 없으면(첫 회) 회의록과 은주 답변으로 새로 만든다.
4. **주제 고르고 원문 요청.** 후보 3개를 이유 한 줄씩과 함께 제시하고 은주가 1~2개 고른다.
   - 후보 순서: 추적표 🟡 조치의 대상 문의 → 회의록 VOC 특이사항 → 돈·신뢰가 걸린 고객 피해 → 새로 튄 것 → 3주 연속 추세.
   - 빼는 것: 최근 4주 안에 원문을 읽었고 그 사이 조치가 없는 주제 · 회의록 태그 결정으로 설명되는 변화.
   - 은주는 채널톡에서 태그를 직접 골라 뽑는다. 주제마다 핵심 태그 2개(많아도 3개)와 건수, 나머지는 선택으로:
     ```
     주제 B. 자격증 신뢰
     핵심: 아카데미_자격증가치/효용성 (65건) · 아카데미_자격증/상세정보 (58건)
     선택: 아카데미_자격증/발급방법 (13건)
     기간: 09/07~09/13 → export 파일을 voc-원문/0914/에 올려주세요.
     ```
   - 같은 메시지에서 "회의록에 없는데 지난주에 반영된 조치가 있나요?"도 묻는다.
5. **원문 전체 분류.** 표본이 아니라 **올라온 원문 전부**를 분류한다(은주 지시). `sample_chats.py --chunk 40`으로 묶음을 만들고, 묶음마다 하위 에이전트에게 **같은 원인 기준표**로 맡겨 상담 한 건당 한 줄(JSONL)을 받는다(프롬프트 틀은 `data.md`). 건수는 `tally.py`로 센다 — 에이전트가 센 숫자를 쓰지 않는다. 빠지거나 겹친 상담이 있으면 그 묶음을 다시 맡긴다. 직접 5~10건 읽어 에이전트 분류와 대조한다. 원문이 없는 주제는 건너뛴다.
6. **4주 숫자.** 고객이 막힌 곳 **덩어리마다** 그 결론에 해당하는 태그 묶음을 정해 `trend.py`에 넣는다(주제 전체 묶음 아님). 출력의 `📎 태그 묶음` 줄도 리포트에 붙인다 — 다음 주에 같은 묶음으로 이어 보고, 추적표 판정도 같은 줄로 한다.
7. **초안.** `report-format.md`대로 쓰고 은주에게 핵심을 보여 승인받는다. 리포트에 넣기 곤란한 응대 이슈는 은주에게만 따로 알린다.
8. **노션 저장.** 제목 `26년 9월 7일~13일 VOC 리포트`(달을 넘으면 `26년 8월 31일~9월 6일 VOC 리포트`, 연도는 실행 시점). 저장 후 다시 열어 두 파트가 다 들어갔는지 확인하고 URL과 근거 링크 파일 위치를 알린다.
9. **마무리.** 변경 요약을 보고하고 "GitHub에 push할까요? (`cspush`)"를 묻는다.
